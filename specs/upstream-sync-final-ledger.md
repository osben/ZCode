## controller

Scope: `packages/services/src/window-controller/windowHostControllerService.ts` (the fork's home for
the window host controller) against upstream 0a1fc56d
`packages/desktop/src/host/windowHostControllerService.ts` and its desktop tests. Result: the four
desktop files pass 41/41. Fork guards kept throughout (`assertOpen`, `maxSources`, bounded reads,
convergence and incognito writes, the single runtime unread producer).

Ported from upstream:

- Source identity: `sourceKey` uses `sourceServerId ?? remoteSessionId`, the same key the projection
  already uses. A remote scope that carries only `sourceServerId` no longer collapses to
  `undefined`. Rows and scopes carry `sourceServerId` and `serverDisplayName` end to end.
- Live events: an `isCurrentSource()` guard runs before the unread signal fires and before the
  follow-up refresh. Replaced, offline and disposed sources emit nothing. A failed follow-up refresh
  goes to `onSourceError` and never swallows a signal that already fired.
- `getTaskMeta`: the address is parsed with `windowHostTaskAddressSchema`. Owner and source are
  re-checked before and after the IO, including the attachment's remote session ID and the address
  identity. A changed owner, a disposed attachment or an address mismatch rejects with
  `任务读取期间 source 已失效` or `任务地址与 source 不匹配`.
- `mutateTask`: the source must be online, or the call throws. Mark-read and mark-unread wait for an
  in-flight read, then re-read only when the row is missing. Both return the committed reply,
  normalized to the source scope; the unread compare-and-swap uses that reply, not a later
  projection. Error: `未读写入期间 source 已失效`.
- `resolveTaskAddress`: the attachment is re-checked after the first snapshot load. A row is matched
  by `sourceServerId` when the source has one, so a Source-only sidebar query can be followed by an
  attachment. The `allowMissingTask` fallback keeps `sourceServerId`.

Decisions that differ from upstream:

- `createAttachmentService(ownsUnreadSignals = true)`. Default `true` keeps the fork's always-on
  unread stream for every attachment, because the fork's sidebar unread writer
  (`useProjectUnreadSignals`) runs on every attachment. A passive attachment (`false`) gets
  `Event.None`, which the upstream test requires. Each attachment forwards from the runtime emitter
  and disposes its own subscription, so a disposed attachment gets no signals.
- `getTaskMeta` throws when the owner is unavailable (the fork returned `null`). The UI caller
  (`readProjectTaskMeta` in `useProjectUnreadSignals`) is inside a `.catch`, so a throw is treated as
  no compare-and-swap basis.
- Post-write refresh: a forced refresh that joins an older in-flight read reports that read's failure
  a second time; the post-write refresh waits for the in-flight read to settle, then reads again
  (test: `delivers the explicit completion of a known task even when its projection refresh fails`,
  exactly one `onSourceError`).

Not changed: `ZCodeTaskListWorkspaceScope` (services) still has no `kind` or `sourceServerId`; the
controller reads `sourceServerId` from its own `WindowHostControllerSourceScope`, so the shared
protocol needed no change.
