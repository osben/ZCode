# Build pipeline entrypoints

## Ownership and format

The checked-out Desktop remote runtime consumes the component manifests generated by
`scripts/prepare-prebuilds.mjs`: `packages/desktop/mock-cdn/releases/<version>/manifest-<target>.json`.
That script remains the single owner of remote resource generation. The standalone
Server CLI `stage` command packages a different release layout and is not a substitute
for the Desktop mock CDN pipeline. Do not add the absent Source Server release protocol
as part of an entrypoint repair.

Root `prepare:remote-assets` invokes the existing generator. The Desktop package alias
forwards to the root script so E2E and source development use the same command.
`bootstrap:with-remote` uses that root entrypoint too. `prepare:remote-assets:linux`
selects only linux-arm64 and linux-x64; the default command retains all four POSIX
targets. A completed generation writes the existing per-target manifests after its
component artifacts. No task/session ownership, protocol, persistence or database
migration semantics change.

```text
Desktop build / E2E / bootstrap
  → root prepare:remote-assets
    → prepare-prebuilds.mjs (single generator)
      → runtime bundles + native binaries + notices
        → component archives + per-target manifests
          → existing Desktop remote loader
```

The Desktop tsup host bundle maps `host/tasksStorageWorker` to the existing
`src/host/tasksStorageWorker.ts`. The emitted `out/host/tasksStorageWorker.js` remains
colocated with the Host code that creates the Worker.

## Acceptance

- All remote asset aliases resolve to existing source entrypoints.
- Default and Linux-only target selection preserve the established manifest layout.
- Every explicit tsup entry points to an existing source file; the storage worker
  keeps its existing output location.
- Run focused regressions and the real preparation/build commands. Report missing
  external toolchains, network failures, or native artifacts separately from code failures.

## Shared-sync compatibility

A workspace build includes the Agent contracts and bootstrap, beyond the root typecheck.
Keep the existing session archive fields (`session.list.includeArchived`, default false,
and optional nonnegative `session.archivedAt`) in the wire schema while their current
CLI handlers still implement them. This is an additive compatibility repair; no storage
or migration definition changes.

Highspeed metadata and execution fallback events in Agent contracts accept the same
three reasons as the shared schema, including `highspeed_selection_unavailable`.
Use one Agent metadata type as the owner of that reason set, and retain the public
exports. Cold hydration and persistence preserve the selection-unavailable reason.

The shared wire schema can describe background execution overrides from newer runtimes.
This Core's execution-scoped child policy remains foreground-only. Its bootstrap
projection explicitly rejects `background: allow` before execution and preserves
`background: deny`; it must not silently reinterpret the unsupported policy.
