# UI upstream 3.16.1 sync: fork re-application ledger (bucket 4)

Scope: the 33 files of bucket 4 that carry fork code changes (18 more have no fork code diff and take
upstream as-is). Base = aac4755666d0 (v3.15.1), fork = 9c2434f7, upstream = 0a1fc56d (v3.16.1).

Method notes (recipe validation):

- The recipe's `forkCodeDiffSize` is a line count that includes comment and formatting churn. Files whose
  fork-vs-base diff is comment or formatting only were taken from upstream (no fork code to re-apply).
- A token-level diff (ignores whitespace, trailing commas and comments) is the reliable way to see the
  real fork hunks. Use it before reading raw diffs.
- For large files where upstream changed little, `git merge-file -p ours base theirs` produced a clean
  candidate (CommandCenterDialog: 3 conflicts, all import and comment lines). Verify the candidate against
  upstream's own hunks.
- `git merge-file --ours` on test files is NOT safe: when upstream removed an import that the fork's test
  body still uses, `--ours` keeps the body and drops the import (ReferenceError at run time). Each such
  test needed its imports or helpers restored by hand (see the test table).
