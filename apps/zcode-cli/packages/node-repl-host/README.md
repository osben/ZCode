# @zcode/node-repl-host

The shared host for `node_repl`: the JavaScript execution surface (with only one tool, `js`) and two domain bridges (Browser Use and Computer Use) live here.

## Why It Is a Separate Package

The host is shared by **official capabilities** and does not belong to any one plugin. It used to live in `browser-use-plugin`, which meant:

- Changes to Computer Use required changes to the browser-use package.
- The CUA SDK and documentation each had a manually maintained duplicate in browser-use.
- `resolveBuiltInNodeReplMcpServers` looked for host artifacts only under browser-use's `rootPath`; if browser-use was missing, CUA could not get the host even when enabled on its own.

Registration already lived in the CLI core (`bootstrap/src/app/built-in-node-repl.ts`, enabled when either BUA or CUA is enabled). The missing piece was **artifact ownership**. This package puts the source in the right place.

## Artifacts Are Still Carried by the Plugin Package

`dist/mcp/server.js` and `scripts/computer-use-client.mjs` are in the SEA release manifest (`OFFICIAL_BROWSER_USE_REQUIRED_SEED_PATHS`), so their paths cannot change. Therefore, browser-use's build bundles output from this package's `src/server.ts`; the CUA client and documentation copies are generated by build scripts instead of being maintained manually.

Moving the artifacts out of the plugin root also requires changing the SEA manifest and bootstrap's `hostPackage` resolution. That is a separate step.
