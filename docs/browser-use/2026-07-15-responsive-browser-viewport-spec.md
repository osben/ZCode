# Embedded Browser Responsive (Free-Size) Viewport

> Coordinates and CDP reconnect contract (2026-09-07): see the [Desktop zoom coordinate spec](2026-09-07-desktop-zoom-coordinate-spec.md). Raster compensation is kept and input is converted by the applied metrics scale; main normalizes guest zoom when setting/replaying a viewport, and replay must not be skipped inside the screenshot critical section.
>
> Since 2026-10-16 the zoom-in levels also use renderer layout compensation (webview layout x 1/zoom + scale(zoom)); CDP metrics no longer carry a scale and input is no longer multiplied. The 2026-07-22 "guest metrics zoom-in compensation" described below is superseded; the reason is in the same spec under "page grows and shrinks after CDP idle detach".

Status: implemented. Dated 2026-07-15 and extended through 2026-08-30 (screenshot pixels, timeout re-entry and horizontal scroll chain; top size inputs, preview zoom, tall viewports, out-of-range feedback, default Fit, vertical scroll chain, silence for model-initiated open/resize, global-zoom isolation and guest compositor cover/shrink compensation; Retina visible surface decoupled from DPR=1 page metrics, default size by tab creation source, screenshot raster self-correction, screenshot first-frame CSS 1x baseline, high-quality host downsampling for dynamic sizes; Desktop zoom dynamic Fit re-measure and the guest-zoom normalization order after metrics; logical normalization of the screenshot surface-ready size under negative Desktop zoom; cancel semantics when the window loses focus mid-drag; stable Fit first frame on multi-tab switch; cross-restart persistence of the human user's display preference with Agent isolation).

| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

Browser Use keeps controlling a single Agent tab independently through the Playwright-isomorphic `Tab.setViewportSize()`. |

| Out of scope          | UA, touch, orientation sensors, network throttling, device list, page-level zoom, Browser Tab/URL/history cross-restart recovery, independent Web/mobile Browser runtime                                                                                                                                                                                      |

| 21 | Keeping sharpness when the returned raster is larger than the CSS viewport | Sizes are dynamic (no hard-coded `2560 x 1440 -> 1280 x 720`). | 22 | PNG size equals the CSS viewport yet content is blurry | A real post-restart artifact was `1280 x 720` but blurry while CDP `scale: 1` later returned a sharp `2560 x 1440`: IHDR size alone is insufficient. | 23, 24 | Why the guest still left blank right/bottom with Desktop zoom `+2` | Round 23's delayed-transform replay was a misdiagnosis; a stable direct guest-target capture showed the PNG itself covered only `1/1.21` top-left. (Superseded for zoom `> 1` by the 2026-10-16 note.) |
| 25 | Why screenshots time out in surface preparation under negative Desktop zoom | Windows trace at `desktopZoomLevel=-2`: the `<webview>` raw layout of a logical `1280 x 720` viewport was inversely expanded to ~`1549 x 871`, and the ready hook compared the raw offset with the logical viewport, so ready was never sent. The ready check must normalize raw layout to the logical CSS viewport with the applied `data-browser-layout-scale`, keeping the guest id and two-consecutive-stable-frame protections; a longer default budget (1500ms -> 3000ms) only accommodates slow surface stabilization and must not replace the correctness fix. |
| 26 | Converging the gesture when the window loses focus mid-drag | Triggering the OS screenshot shortcut mid-drag lost the pointer-up and later plain mouse moves kept resizing. `window blur`, `pointercancel` or `lostpointercapture` immediately end the drag, commit the last observed size and release capture; a new drag needs a fresh handle press. |
| 27 | Why multiple Fit tabs flash `100%` before fitting on switch | A hidden tab's canvas was `0x0` and the ratio fell back to `1`; after switch-back it recovered ~13ms later. A non-positive size from `display:none` has no layout authority and must not overwrite the last valid canvas; when the tab is composed again the current canvas is re-measured synchronously before first paint so the first frame uses the right Fit ratio. |
| 28 | Restore the human's last display config on next user-opened URL? | Yes: last user-chosen normal/free mode, fixed resolution width/height and Fit/fixed percentage, only for user-opened URLs. The preference is persisted as app-global `AppSettings`, read once at creation of a new human Browser tab; Agent creation, claim, navigate and viewport set/reset neither read nor write it. |

## Boundary Decisions

| Boundary | Decision | Excludes / prunes |
| -------- | -------- | ----------------- |
| Human browser initialization | A new human Browser tab reads the human display preference once at creation. Without a saved preference it stays normal full-fill and the first manual entry into free size uses `393 x 852` CSS px; with a preference it restores normal/free mode, last width/height and Fit/fixed percentage. Includes user-opened URLs, new blank Browser tabs, and the next human tab after the same app or a full restart. | Browser Use/Agent-created tabs; live sync of existing tabs. |
| Model-created default | Both explicit `browser.tabs.new()` and implicit creation by the first command when no tab exists start at free size `1280 x 720` CSS px (foreground/background IAB tabs). | Claiming an existing user tab, reusing an existing controlled tab. |
| Existing-tab size retention | The human preference only initializes new tabs; later settings sync or changes in other tabs never overwrite an existing tab live. claim, activate, navigate/goto, back/forward, reload only reuse the current mode and size and never re-apply preference or defaults because the operator became the model or the page changed. | `setViewportSize()` / viewport reset and user toggle/input/drag still change it. |
| Size range | Width and height minimum `320`; width max `3840`, height max `2160`. | Zero size or infinite canvas. |
| Size info | In free-size mode `width x height` is shown between the address bar and the canvas as two editable number inputs; updates from drag or Agent sync into them. Separate from page content; commit on Enter or blur; the narrow pane scrolls horizontally. | A duplicate label at the viewport bottom; overlaying page content. |
| Size input validation | Only integers inside the existing strict range are submitted; empty, non-integer and out-of-range values keep the draft and show a range hint, with no partial update; clear the error once corrected. width `320..3840`, height `320..2160`, `aria-invalid` and a visible tooltip. | Silent revert, silently widening the protocol range, an illegal intermediate state after updating one axis. |
| Zoom levels | Each manual entry from normal mode in an existing tab defaults to `Fit to window`; options `50% / 75% / 100% / 125% / 150% / 200%`; viewport sync while already in free size does not reset the current choice; the human-chosen level goes into the display preference and is restored exactly for the next human tab. Renderer-local preview state, human app-global preference, stable guest identity. | Agent preference read/write, arbitrary custom percentages. |
| Fit to window | Scales down proportionally within the available canvas, max `100%`; recomputed when the canvas or viewport changes. A hidden tab's `0x0` observer sample must not overwrite the last valid canvas; when composed again it is re-measured before first paint so the first frame already has the correct Fit ratio (no `100%` flash across multiple tabs). | Zooming above 100%, changing the CSS viewport, clearing a valid ratio from a hidden layout sample. |
| Zoom vs. viewport | A percentage changes only the visual ratio and canvas footprint in the host renderer; the guest CSS viewport, media queries, screenshot pixels and Browser Use readback are unchanged. Transform scale, drag delta converted by ratio, only the CDP metrics scale that corrects native raster coverage. | `webFrame.setZoomFactor`, changing the guest CSS viewport, page zoom. |
| Global zoom isolation | The free-size frame uses the reciprocal of the current Desktop zoom factor to cancel the parent renderer zoom and pins `<webview>` guest zoom to `1`. At zoom `> 1` the `<webview>` stays `100% x 100%` and main corrects native raster coverage with the same zoom factor in guest metrics (2026-07-22 design; superseded for zoom `> 1` by the 2026-10-16 note above). At zoom `< 1` no fractional metrics scale is used; the absolutely positioned layout size keeps expanding to `100% / zoom` and is then scaled, so the transformed surface equals the frame, full guest content is not cropped, and the untransformed layout size does not enter the canvas scroll extent. Fixed percent and Fit semantics unchanged; on exit clear metrics and restore the current app zoom. Covers global zoom levels `-3..+5`, runtime switching, Web fallback `1`, guest surface coverage and content integrity. | Normal full-fill mode, top toolbar, page-initiated zoom, independent Web/mobile runtime. |
| Page metrics vs. visible surface | The free-size CDP `deviceScaleFactor: 1` constrains only the guest CSS viewport and screenshot pixels. When setting metrics keep the `<webview>`'s current visible surface size; Electron DOM layout allocates the native canvas by the host Retina backing scale. Size switching is still done by the renderer changing `<webview>` bounds; on exit clear the override. Covers Retina/non-Retina, Fit/fixed ratio, Desktop zoom=0 with existing zoom compensation. | Host-DPR screenshots, extra CSS DPR compensation, Web/mobile runtime. |
| Desktop zoom guest compensation | In free size the guest zoom is pinned to `1`. At zoom `> 1` (2026-07-22 design, see note) the renderer resends the current viewport on every zoom change and main reads the real zoom factor from the trusted BrowserWindow, stores it on the tab and replays `Emulation.setDeviceMetricsOverride(scale: zoom)` with the viewport; `<webview>` no longer uses an enlarging transform. At zoom `< 1` metrics scale stays `1` and the renderer keeps `1 / zoom`-times absolutely positioned layout with synchronized `scale(zoom)` converging to the frame; zoom `= 1` adds no compensation. No compensation rebuilds the webview or changes the viewport, DPR, visualViewport, screenshot target or Agent state read back from the guest. Covers `-3..+5`, Fit and fixed ratios, dynamic switch/reset, guest remount. | Changing guest page zoom, asserting only DOM bounds, rebuilding the webview, fractional metrics scale for zoom-out. |
| Control bar visual hierarchy | Single-row `h-8` quiet background; width/height inputs and zoom trigger are transparent by default with no permanent border and compact width; hover shows a weak background; focus uses the input focused token; keep editability and accessible focus. Long text scrolls horizontally. | Three separate white input boxes, permanent card borders, removing keyboard focus. |
| Resize handles | Four edges adjust the corresponding axis, four corners adjust both; corners are icon-less hit areas; edge separator icons appear only on hover/focus and support arrow keys. Pointer, touch pen, keyboard. | Permanent separator icons, visible corner arrows, inaccessible single corner marks. |
| Drag cancel | The drag gesture is bounded by pointer capture. Window blur, `pointercancel`, `lostpointercapture`, mode exit or component unmount all end the gesture and clear any pending frame. After refocus, movement without a new `pointerdown` must not change the viewport. Covers macOS screenshot, app switch, Windows/Linux blur, capture revoked by the browser. | Persisting drag state, treating window focus as continuing the drag, changing the Agent viewport recovery semantics. |
| Mode exit | Clicking again restores full fill and writes the human preference mode as normal, while keeping the preference's last free width/height and zoom; re-entering free size in the same existing tab restores the last free size and resets preview zoom to Fit. | Agent create/control paths, existing tabs overwritten live by settings broadcasts. |
| Page behavior | The CSS size changes so the guest triggers its own resize/media queries; the free-size override pins `deviceScaleFactor: 1`. Renderer DOM layout, CSS viewport and screenshot pixels are 1:1. | UA/touch/network emulation. |
| Resize during an Agent operation | User toggle/input/drag of free size or external layout changes keep triggering the existing weak prompt; model-initiated Browser open or viewport set/reset does not prompt; tools are not cancelled. Only coordinate-system changes the model did not initiate are flagged. | Reverse prompt for model-known changes; modifying Agent state. |
| Clients | Shown only on the existing Desktop embedded-browser capability (desktop local/remote workspaces share the renderer capability). | New Web/mobile runtime. |
| Agent API | Aligned with Playwright `page.setViewportSize({ width, height })`, in ZCode `tab.setViewportSize(...)`; `tab.viewportSize()` returns the actual value bound by the latest `tabs.list()/get()`. Single-tab size setting, isomorphic naming and parameter shape. | browser/session-wide size as the main API. |
| TabInfo size | Every controlled `TabInfo` from `browser.tabs.list()` must contain `viewport: { width, height }`, the guest's actual CSS viewport (normal/free-size, active/background tabs). | Returning only the override, a value inferred from UI labels. |
| Agent auto linkage | `tab.setViewportSize()` auto-expands the target tab, enters free-size mode and syncs the frame without affecting other tabs. Main->renderer directed notification, stable `<webview>` identity. | Only doing CDP emulation, broadcasting to the whole scope. |
| Agent out-of-range | Width only integers `320..3840`, height only integers `320..2160`; both the SDK and the runtime schema reject explicitly. Boundary values succeed; out-of-range and non-integers fail. | Silent clamp, partial apply. |
| Screenshot timeout layering | The default execution budget of `mcp__node_repl__js` is 60s; the host->main browser command keeps a 30s sub-budget, leaving time for JS wrap-up, image processing and a structured error return. Two explicit deadlines, the browser sub-command fails first. | Both layers at 60s with a racing timeout. |
| Screenshot re-entry | At most one underlying `Page.captureScreenshot` per tab at a time; an outer timeout only ends the wait, and a new screenshot before the underlying one settles returns an explicit error immediately without stacking CDP requests. Covers late completion after timeout/cancel and later recovery. | Unbounded concurrency, silent queueing, retrying as-is. |
| Screenshot raster self-correction | A free-size screenshot issues its first capture with the dynamic CSS clip and `scale: 1`; legacy backing metrics do not take part in the first-frame scale. After decoding the PNG IHDR: an oversized proportional first image is downsampled directly with the host image engine at `best`; a first image exactly equal to or proportionally smaller than the target, if host downsampling is available and the dynamic quality budget allows, triggers a single `scale > 1` supersampling capture (target at most 2x, long edge at most 4096, total at most 16MP) and is then downsampled to the target. At most two captures overall; on non-proportional deviation or processing failure keep the successful image with the most information. Any legal viewport, clip, fullPage and Playwright element screenshot share the executor; integer and non-integer DPR; large sizes converge to 1x within the quality budget. | Hard-coded pixel sizes or host DPR, looping retries, CDP re-render at `scale < 1`, exceeding the pixel budget, handing a low-res image to the model compression layer to enlarge. |
| Screenshot surface-ready size | While the renderer waits for the screenshot surface, `getBoundingClientRect()` is only a candidate that can directly hit the logical viewport; raw `offsetWidth/offsetHeight` must be divided by the applied valid `data-browser-layout-scale` on the same `<webview>` before comparing with the requested viewport. Ready only after the guest id is unchanged and the logical viewport is stable for two consecutive animation frames. Covers Desktop zoom `< 1` layout counter-compensation, zoom `>= 1` and missing/invalid scale falling back to `1`, +-1px layout rounding. | Lengthening the coordinator timeout, removing the size check, guessing the viewport from the parent container, treating preview Fit/fixed zoom as the guest viewport. |
| Guest scroll chain | In free size, when no scrollable element inside the `<webview>` guest can consume that direction, the fixed preload forwards a validated delta to the embedder renderer to drive the outer canvas; normal mode ignores it. Covers `deltaX/deltaY`, Shift+wheel, nested scroll container boundaries. | Masking the webview, unconditionally taking page scroll, the page owning Electron IPC directly. |

## Domain Scope And High-risk Cross-products

Included domains: UI shell/theme/locale/responsive (new icon, canvas, size label and drag handles must fit themes, i18n, narrow pane; `DESIGN.md`, `packages/ui/src/i18n`); Browser Use lifecycle (human/Agent tabs share `UnifiedBrowserView` and resize can invalidate coordinate actions; Browser parity matrix, `useBrowserResizeOperationWarning`); architecture/process boundary (the Agent->host->main->renderer single-tab command and the actual-viewport readback must share one source). Mobile remote/replayable is excluded: Desktop-only capability, task realtime unchanged.

| Cross-product | Risk | Handling |
| ------------- | ---- | -------- |
| responsive toggle x live `<webview>` | Toggling DOM hierarchy rebuilds the guest and loses history | Stable wrapper hierarchy; test DOM identity |
| resize x Agent coordinate action | User/external change invalidates old screenshots and coordinates; model open/set/reset are known sources | User/external changes reuse BCP-183; model events are silent and do not consume the cycle's prompt quota |
| tab switch x local size | Size leaks to other tabs or is lost on a hidden tab | State held by each `UnifiedBrowserView` instance |
| oversized viewport x narrow pane | Content cropped and unreachable | Responsive canvas scrolls in both directions, viewport centered |
| theme/locale x compact toolbar | Icons or handles invisible, tooltip text incomplete | Semantic tokens + zh/en keys + accessible names |
| zoom x viewport authority | Visual ratio mistakenly written back as the guest CSS viewport | Zoom belongs to the renderer only; manager/Agent still read the real viewport |
| zoom x drag resize | Adding pointer delta directly after zoom scales size changes wrongly | Divide pointer delta by the current visual scale before updating CSS px |
| responsive zoom x Desktop global zoom | Parent renderer zoom multiplies with preview zoom; on zoom-in the guest surface does not follow the frame, on zoom-out symmetric surface scaling leaves blank or crops content; `100%` frame, guest innerWidth/DPR, canvas scroll extent and drag conversion may drift | Subscribe to the current window zoom level; frame transform/footprint reverse compensation; free-size guest zoom pinned to `1`; zoom-out adds an absolutely positioned layout counter-compensation |
| Retina backing scale x DPR=1 override | CDP changing both page metrics and visible surface makes the Retina 2x backing surface allocated at 1x: DOM bounds and guest `innerWidth` are right but the native surface covers only ~the top-left half | metrics override uses `dontSetVisibleSize: true` so CDP changes only page metrics; the visible surface stays managed by `<webview>` bounds |
| fit x pane resize | Stale scale or a feedback loop after a panel change | Observe only the canvas content box; scale never written back to the viewport |
| Agent resize x multiple tabs | The old browser-wide implementation spread the size to all tabs in a scope | A command must carry/resolve the target tabId and update one guest only |
| Agent resize x renderer async delivery | CDP changed but the UI still shows full fill: visual and actual viewport disagree | Main notifies the owner window directly; renderer filters by tabId and enters free size |
| manual drag x Agent CDP override | After the user drags the frame an old override still locks the page size | Renderer writes the current size back to main, updating the same tab override |
| tabs.list x normal/inactive guest | A cache or UI label does not represent the actual CSS viewport | Use the confirmed value when an override exists, otherwise read back guest `window.innerWidth/innerHeight` |
| Retina DPR x large viewport screenshot | A `1920 x 1080` CSS viewport enlarged to `3840 x 2160` adds compositor/PNG pressure and contradicts responsive-test expectations | Free-size CDP override pins DPR=1; after exiting free size clear the override and restore the host natural DPR |
| Retina metrics x capture raster drift | `Page.getLayoutMetrics` still reports a 2x backing surface but `Page.captureScreenshot` outputs 1x CSS raster; applying `0.5` again would shrink `1280 x 720` to `640 x 360` | Calibrate the screenshot scale once from the first PNG's actual pixels; keep the CSS viewport size at the end, then the PNG/JPEG budget policy |
| screenshot timeout x immediate retry | Host already returned timeout while the uncancelable CDP capture still runs; stacked retries time out repeatedly | Manager keeps the underlying in-flight fact per tab; a new capture is explicitly rejected until the old one settles |
| oversized viewport x guest wheel | A `<webview>` guest wheel does not bubble to the embedder; the outer `overflow-auto` cannot move horizontally or vertically with the mouse over the page | The fixed guest preload recognizes scroll boundaries and forwards via `sendToHost` only the delta of the corresponding axis not consumed by the page |
| human preference x app restart | Treating the display preference as Browser tab recovery would also restore URL/history/pageState and reintroduce the retired catalog | Save only mode, width/height and preview zoom in `AppSettings`; a full restart still starts with an empty tab catalog and the preference is read when a new human tab is created |
| human preference x Agent Browser Use | The shared `UnifiedBrowserView` could let an Agent tab inherit the user's fixed size/zoom or let Agent viewport events pollute the preference | The human surface explicitly enables the preference capability; the Agent surface neither reads nor writes; Agent keeps the creation default `1280 x 720` and explicit set/reset semantics |
| preference broadcast x mounted tabs | An app-global settings broadcast driving all instances would suddenly change an existing tab's mode/size when the user acts on another tab | Each human tab consumes the preference once at initialization; later broadcasts serve only future new tabs; the current tab remains owned by local runtime state |

## Concept Map And State Owners

```text

  -> UnifiedBrowserView.isResponsiveMode (current tab React local state)
  -> ResponsiveBrowserViewport.viewportSize (current tab React local state)
  -> stable frame CSS width/height
  -> the same <webview> guest receives viewport resize
  -> page resize / media query

human Browser tab creation
  -> read AppSettings.embeddedBrowserViewportPreference once
  -> normal: stay natural full-fill
  -> responsive: restore width / height / previewZoom

  -X-> does not write the AppSettings display preference

  -> scaled canvas footprint + stable frame transform
  -> pointer drag delta / visualScale
  -> CSS viewport size
  -X-> BrowserGuestManager viewport / screenshot / media query (unaffected by visualScale)

  -> BrowserGuestManager reads the actual CSS viewport per tab
  -> BrowserTabSummary.viewport
  -> BrowserTabInfo.viewport
  -> tabs.get(info.id).viewportSize()

  -> per-tab screenshot in-flight guard
  -> Page.getLayoutMetrics only selects the CSS clip, ignoring the legacy backing/CSS ratio
  -> CDP Page.captureScreenshot(scale=1, captureBeyondViewport=false for viewport capture)
  -> read PNG IHDR dimensions
  -> equals target CSS clip: return first capture
  -> uniform mismatch: adjustedScale = firstScale x targetSize / actualSize
  -> retry Page.captureScreenshot once, choose result closer to target
  -> host->main 30s sub-budget
  -> success: clear in-flight; in free size output pixels are 1:1 with the CSS viewport
  -> outer timeout: return a structured timeout; a new screenshot before the underlying one settles fails explicitly and is not dispatched again
  -> late completion: clear in-flight, later screenshots recover

guest wheel (consumed by the host only in free size)
  -> a guest ancestor scrollable in that direction exists: leave it to the page
  -> no scrollable guest ancestor, and the page did not preventDefault
  -> fixed preload sendToHost(wheel-boundary, deltaX/deltaY)
  -> embedder <webview> ipc-message
  -> responsive canvas scrollBy({ left: deltaX, top: deltaY })
```

## E2E Handoff Notes

- No provider, filesystem fixture, Docker or conversation replay fixture is involved.
- Primary automated evidence is in `packages/ui/test/UnifiedBrowserView.test.ts`. In the Browser Use master matrix BCP-194 covers the basic free size, BCP-205 the top inputs, preview zoom and Desktop global-zoom isolation, BCP-231 human preference restart recovery and Agent isolation; BCP-195..198 cover the protocol command; BCP-199..200 lock DPR=1 screenshot pixel semantics and per-tab screenshot backpressure (the 30s browser command is an internal sub-budget of the 60s Node REPL tool and does not change conversation/tool timeout); BCP-201 the guest scroll forwarding (fixed preload forwards only scroll deltas the guest cannot consume; nested page scrolling first; no change to the Browser Use API or task realtime). The protocol command stays a one-shot browser RPC, outside conversation stream/snapshot, and does not change the desktop-continuous / web-remote-replayable delivery semantics.
- Electron smoke uses an ordinary human tab: the guest switches from full fill to `393 x 852`, top size inputs and zoom levels work; each corner drags in its own direction to `426 x 600`; corners show no icon, edge separators are transparent by default and shown on hover; the same `<webview>` target stays mounted.
- RBV-032 evidence rule: DOM bounds or guest metrics being equal is not a substitute for visual evidence; the compositor surface coverage must be verified. At Desktop zoom `+2`, the embedder `devicePixelRatio` is `1.21` times the base Retina DPR, frame and `<webview>` DOM bounds are both `393 x 852 x rendererScale` and the guest still `393 x 852 / DPR 1`, yet the native guest surface was composed at the base DPR only, leaving a right/bottom blank exactly `1.21`; after the fix, Fit and fixed `50%` coincide with the frame on four edges with the guest CDP at `393 x 852 / DPR 1 / visualViewport scale 1`, a real embedder pointer at the frame center reaches the guest at `(196.25, 426.23)`, and exiting free size clears the webview compositor compensation and restores guest zoom (`1.21` for the app zoom; re-entry to default Fit pins it back to `1`). At zoom `-2`: only `scale(0.826446)` gave a `429 x 931` frame with a `355 x 769` guest surface and blank right/bottom; removing the transform filled the frame but enlarged and cropped the bottom; an absolutely positioned `121% x 121%` layout then `scale(0.826446)` made Fit and fixed `50%` coincide with the frame, the full bottom input visible, Fit canvas `scrollHeight === clientHeight`, guest `393 x 852 / DPR 1`, frame-center pointer mapping to `(196.72, 425.96)`.
- 2026-07-22 correction (zoom `+2`, factor `1.21`; the metrics-scale design later superseded for zoom `> 1` by the 2026-10-16 note): the earlier "replay the transform after two frames already fills" was a misjudgment of a temporary host style. A direct `Page.captureScreenshot` on the guest target covered only `325 x 704`, exactly `1 / 1.21` of `393 x 852`, so the root cause is in the guest metrics/native raster, not React commit timing. Setting `Emulation.setDeviceMetricsOverride({ width: 393, height: 852, deviceScaleFactor: 1, dontSetVisibleSize: true, scale: 1.21 })` with the webview kept at `100% x 100%` fills both guest and host screenshots, with the guest still reporting `393 x 852 / DPR 1 / visualViewport scale 1`.
