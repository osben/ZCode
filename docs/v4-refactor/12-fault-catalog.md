# Fault Catalog: the `fault.*` Protocol Error Enum (G-12)

This document organizes the environment faults of [conversation-session-environment-fault-catalog.md](../testing/conversation-session-environment-fault-catalog.md) into `fault.*` reasonCodes and the `SessionErrorInfo` mapping, and records the product rulings that are still open.

Current code fact: `SessionErrorInfo.code` and the ACK `reasonCode` are still `string` in the schema and are not mechanically closed by a zod enum; besides the environment faults in the table below, the implementation also uses execution/transport errors such as `fault.command.*`, `fault.subscription.*`, `fault.attachment.*`, `fault.projectionEventCommit.*` and `fault.runtime.*`. This document is therefore the environment-fault base table, not the complete runtime code enum. A new code should still be written back into the matching spec, but it cannot be claimed to be enforced by the type system today.

Three scopes to keep apart:

1. **Environment code base table (defined here)**: stable naming and default classification of provider/network/storage/lifecycle/workspace.
2. **Execution and transport codes**: follow the current handler/gateway code and `10-protocol-spec.md`; they should later be filled into this directory's protocol table.
3. **The product behavior of each fault**: still ruled one by one by the decision worksheet. The table keeps `decision-needed`, meaning the code may still use a generic fallback rather than a confirmed product semantic.

## 1. Structure

```ts
interface SessionErrorInfo {
  code: string; // the fault.* vocabulary here (or proto.*, see 10 §6.2)
  message: string; // fallback English; localized copy is generated by the client from code
  recoverable: boolean; // true -> the UI offers a retry entry
  at: Timestamp;
  source: "provider" | "runtime" | "tool" | "network";
  attribution?: {
    source?: "provider" | "runtime" | "tool" | "network";
    reason?: string;
    providerId?: string;
    modelId?: string;
    providerKind?: string;
    transport?: "http" | "sse" | "websocket";
    statusCode?: number;
    providerErrorCode?: string;
    retryable?: boolean;
  };
}
```

`attribution` is an optional fact layer for compatibility with old events and old persisted data and carries no product policy. The CLI projects it from known error context by whitelist and keeps it identical between live TurnError and persisted cold hydration; it must not carry URL, header, token, request/response body, prompt/tool content, stack, full detail or requestId. When `attribution.source` exists, `SessionErrorInfo.source` takes that value; when absent it falls back to `runtime`. `attribution.retryable` describes only the failure fact and does not replace this layer's `recoverable`, so it does not change the UI retry entry.

Namespaces (parallel to the reasonCode namespaces of 10-protocol-spec §6.2):

| Namespace           | Semantics                                                         | Matching fault catalog group |
| ------------------- | ----------------------------------------------------------------- | ---------------------------- |
| `fault.provider.*`  | The provider returned an explicit failure response                | N01-N05, N08                 |
| `fault.network.*`   | The request/stream failed or was interrupted at the network layer | N06-N07, S01-S07             |
| `fault.storage.*`   | Local filesystem/storage failure                                  | D01-D05                      |
| `fault.lifecycle.*` | Interruption caused by the process/app lifecycle                  | L01-L08                      |
| `fault.workspace.*` | External environment change of workspace/tool                     | W01-W05                      |

Cross-session isolation (X01-X03) produces no code of its own: it asserts "A's fault does not pollute B" and reuses A's own code.

## 2. Vocabulary

The `Decision` column is the ruling state of that fault's product behavior (from the fault catalog / decision worksheet); `recoverable` is the protocol default and a ruling may override it.

| ----------------------------------- | ------------------------------------------------------------------------------ | ------- | ------------------------- | ----------- | --------------- |
| `fault.lifecycle.agentExited`       | CLI/agent process crashed or exited abnormally                                 | runtime | true (restart and resume) | L06         | decision-needed |

> L01/L02/L04/L05/L07 (background, window close, renderer/host crash, sleep-wake) are **not conversation faults** under the v4 architecture: they are connection-layer events absorbed by the `subscribe(base)` recovery path (04-sync-and-recovery) and do not enter `SessionErrorInfo`. This is v4's semantic simplification relative to the old architecture: "display is volatile, facts are persistent".

## 3. Constraints

1. **The goal is a closed vocabulary, not yet mechanically implemented**: a new environment code should first update this document; a new execution/transport code should update the field-level protocol in step. Eventually the stable set should converge into a shared schema instead of staying arbitrary strings long term.
2. **code is not display copy**: the client looks up localized copy by code (i18n), `message` is only a fallback English text; the UI must not parse message strings for logic branches.
3. **`recoverable` drives the UI retry entry**. Relation to row-level `canRetry`: the session-level `lastError.recoverable` controls the retry button of the error banner; the row-level `canRetry` controls that turn's re-run entry; the reducer computes the two separately.
4. **The X-group isolation assertion** goes into golden tests: inject any fault into session A and assert that session B's projection is byte-for-byte unchanged.
5. The product-behavior rulings of the 37 decision-needed items continue through the existing decision worksheet flow (the suggested next batch is N01-N08 + S01-S07, which decide the entry conditions of `phase=error`); ruling results are written back to the `Decision` column of this document.
