# ZCode stdio Tap Proxy

In development, the Help menu item `Capture Agent stdio Traffic` routes the stdio NDJSON between the
app and the ZCode Agent through a side proxy.

## Behavior

- The menu item is shown and effective only in local development runs; test/production installers do not show it.
- The switch state is written to `~/.zcode/v2/dev/zcode-stdio-tap.json`.
- Capture files are written to `~/.zcode/v2/dev/stdio-traffic/<workspaceHash>/`.
- `latest.txt` points to the latest `.ndjson` file generated by the proxy.
- An already-running agent is not restarted; the switch only affects agent processes started afterwards.

## Viewing

The `stdio 抓包` (stdio capture) page of `apps/dev-docs` reads the most recently updated `.ndjson` under
`~/.zcode/v2/dev/stdio-traffic` through a local Vite API and shows records in reverse time order.
Status `real tail` means the data comes from a real tap file; `mock replay` is for manual demos only
and is not real agent traffic.

```sh
cat ~/.zcode/v2/dev/stdio-traffic/<workspaceHash>/latest.txt
```

With the file path from `latest.txt`:

```sh
tail -f <traffic-file>.ndjson
jq 'select(.direction == "app-to-agent") | .message' < <traffic-file>.ndjson
jq 'select(.id == 7)' < <traffic-file>.ndjson
```

Each record keeps `direction`, `raw`, `message`, `parseError`, `id`, `method`, `sessionId` and
`inputId`. `raw` is the original stdio line; `message` is a structured copy when it parses as JSON.
