## 4. SPEC-GAP questions (need owner decision)

1. **B-matrix vs intent-only switching (B1/B2/B3/B7):** QA matrix expects immediate switch + “git unchanged before send”; implemented spec `composer-branch-switcher-semantics.md` §1/§4 (2026-10-15) makes selection intent-only and create+switch happens at dialog submit. Which is authoritative?
2. **Per-file stage/unstage/discard (H1):** declared Non-Goal in `docs/git/requirements.md` §3.3/§7/§10 but expected by the QA matrix; placeholder code + unused i18n keys exist. Future scope?
3. **Workspace-header git entry (§1.1/§1.4):** spec places “Commit or push” in the workspace header; code renders it only in a live session status panel → clean-tree push unreachable without dirtying the repo (hit in H3/H5/B1). Spec stale or code deviation?
4. **D3 global worktree dir** is `join(homedir(), ".zcode", "worktrees")` — ignores `dataBaseDir` (`desktopMainIpcPlatform.ts`). Should it follow `dataBaseDir`?
5. **D7 symlinked workspace** is a separate identity: no realpath canonicalization for project overrides or the sibling container. Intended?
6. **E2/C8 branch prefix:** `composeBranchName` always applies the effective prefix, so typing an exact existing branch name (“release”) produces `<prefix>/release` and the “already checked out” acceptance paths (WT-G3/G4) are unreachable when a prefix is set. Should exact match bypass the prefix?
7. **C10 creation delay:** spec says “five-second delay”; code default is 0 (`worktreeCreation.ts:52-57`; commit b26f5c75 removed a TEMP test delay). Update spec or restore a gated delay?
8. **E4 stale open UX:** spec defines no behavior for “Open worktree” on a stale record (related to BUG-GWT-007; expected behavior = recoverable error per WT-04?).
9. **C4 draft loss:** does `composer-worktree-setup-steps.md` §Submission cover text typed into the disappearing empty-state editor?
