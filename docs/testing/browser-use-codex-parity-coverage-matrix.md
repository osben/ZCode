# Browser Use Coverage Matrix

Full history: `git show 45f808f7:docs/testing/browser-use-codex-parity-coverage-matrix.md`.

> Goal: turn `iab | extension | cdp`, selection, API, security, lifecycle and multi-client state combinations into executable acceptance, so a happy-path-only test is never declared done.

The first scope of the formal Desktop WDIO E2E, historical regressions and pruning are in `docs/browser-use/2026-07-19-desktop-iab-e2e-spec.md`. "Automated" in this matrix may only mean unit, contract or a one-off manual smoke; only a case whose status explicitly lists `packages/desktop/test/e2e/...` counts as formal Desktop E2E.

## 1. State dimensions

| Dimension       | Values                                                                                         |
| --------------- | ---------------------------------------------------------------------------------------------- |
| Backend         | none / iab / extension / cdp / iab+extension / multiple extension instances / all              |
| Selection entry | exact id / type alias / default / URL local / URL exact tab / URL host hierarchy / invalid URL |
| Client mode     | desktop-continuous / web-remote-replayable                                                     |
| Workspace       | local / SSH / WSL / Docker / same path with different identity                                 |
| Runtime         | fresh kernel / warm kernel / timeout reset / sandbox reset / session close                     |
| Tab origin      | agent-created / claimed user tab / unclaimed user tab / restored / stale                       |
| Tab lifecycle   | open / active / background / handoff / deliverable / finalized / closed                        |
| API family      | navigation / playwright / cua / dom_cua / content / clipboard / dev / dialog / capability      |
| Security        | read-only / preapproved / action-confirm / denied / attempted bypass                           |
| Backend health  | healthy / unavailable / handshake timeout / disconnect / reconnect / stale generation          |
| Result          | direct value / bytes/image / response meta / structured error / uncertain side effect          |

The full Cartesian product is not executable; use boundary grouping, pairwise and risk-first combinations. No pruning may remove cases that cross backend identity, clientMode, workspace identity, security deny or lifecycle cleanup.

## 2. Pruning decisions

| Combination                                        | Decision                         | Reason                                                            |
| -------------------------------------------------- | -------------------------------- | ----------------------------------------------------------------- |
| Playwright as a backend                            | pruned                           | Conceptual error; Playwright is an API family                     |
| extension/cdp returning a stub while unimplemented | forbidden                        | Creates fake availability                                         |
| Mobile building its own backend runtime            | pruned                           | Violates the shared-host attachment constraint                    |
| relay/main holding tab/task state                  | pruned                           | Violates the remote-control architecture                          |
| Remote isolated by workspacePath only              | forbidden                        | Must use workspaceIdentity/remoteSessionId                        |
| Every OS x every API method                        | pairwise                         | OS differences concentrate on install/native host/paths/shortcuts |
| Every browser version x every locator              | pairwise                         | Keep stable/beta and key locators/actions                         |
| All actions while CDP is gated off                 | test invisible/unselectable only | Unsupported members/backends must be hidden                       |
| Retrying via another API family after action deny  | must test                        | Guards the core security boundary against bypass                  |

## 10. E2E promotion gate

Before any slice is marked "done":

1. The matching case changes from "to implement" to an automated case path and result, not just a status wording change.
2. Protocol changes need strict-schema positive and negative examples, legacy-call compatibility and end-to-end correlation tests.
3. Interaction/remote-control cases must state the impact on desktop continuous and web replayable.
4. Extension/CDP cannot be proven done by mocks alone; at least a real Chrome / real CDP smoke E2E is required.
5. The API manifest, runtime object graph and documentation need snapshot/contract consistency tests.
6. `pnpm typecheck` and `pnpm lint` must run, and the uncovered OS / signing / remote-environment risks recorded.
