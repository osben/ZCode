## Pruning

### Todo 88 accepted old-data additions

- Actively choosing a new model uses that model's highest level; a missing/invalid historical level is not auto-filled. This supersedes the old BSM-10/15/17 wording "switching clears" and "show default only, do not save": I20 verifies the real persisted highest level after an active switch, then the request result of a manual high.
- After I20's settings-page save and before cold start, change the isolated fixture's builtin overrides to the shipped old `builtInModelOverrides` / `builtInThoughtLevelOverrides`. The cold start must have Host import them; without any further settings change the three children's real requests still use the specified models and the high level, and the parent request stays max.
- Custom Markdown writes only the formal `model` / `thoughtLevel: high` and injects no unreleased intermediate state; the file is identical before and after cold start and the actual child request keeps high.

- Not covered: already-running agent taking effect immediately after a Settings hot save. The desktop agent initializes early at window start; hot-save behavior is covered by service/UI unit tests and runtime effect by the cold-start chain.
- Not covered: multi-session isolation, remote `/remote`, mobile replayable, queue, stop, edit/fork, compact, background concurrency combinations.
- No workspace-level override; `Explore` without override inherits the main model by default and no longer defaults to lite.
- No call-level model / effort parameter on the `Agent` tool; no hot update, multi-session or remote/mobile state combinations.
- Existing `Agent.model` in historical transcripts is not migrated or rewritten; it only no longer takes part in model selection for a new child runtime.
- Claude runtime-catalog parity uses the confirmed full duplicate matrix instead of the existing DeepSeek `I20` as representative; the first catalog loading uses a controlled UI test and no production test switch is added for E2E.
- The Settings CRUD E2E sends no prompt and verifies no cold-start child, provider request or model-io; those stay with SB/SX so UI save regressions do not spread into CLI/runtime.
- SL is the two-phase regression gate between the post-login App provider snapshot and the desktop continuous workspace runtime catalog: App metadata makes the control usable at once, background reconciliation makes the runtime catalog eventually consistent, and explicit runtime capability declarations still take precedence. Remote workspace, mobile `/remote` replayable, task queue and provider request are pruned.
