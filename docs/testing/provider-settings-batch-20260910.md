## Native and Electron cases (pending unless noted)

- **BR117-N02** (Todo127 desktop refresh chain, pending, `settings/manual-review/pending`): an isolated full Electron app obtains two versioned Built-in URLs through a test HTTPS proxy. The initial version provides test model capacity 500K and request-mapping marker 0.17; after only the test control plane is switched to the new URL, clicking refresh in settings turns the UI to 700K and the real connection-test wire then uses the new marker 0.37. The Personal file and the preset recent-selection cache stay unchanged. It reuses the official download, Account/Registry update and Model creation paths, never writing Active directly or stubbing the Settings View. The proxy replaces only external network responses and does not relax HTTPS validation; no real account, no auto publish. Old-execution freezing is proven by existing Core/SDK tests; this case does not stand in for a running-Model acceptance. It does not replace the mobile shared-host / SSH Environment joint verification and awaits manual promotion.

```text
settings refresh -> Host official download -> test control-plane URL -> test HTTPS CDN
  -> Active atomic replacement -> Account/Registry -> 700K UI
  -> connection test on the new Model -> actual wire 0.37
```

- **K116-N01** (Todo116 native open, pending, `packages/desktop/test/e2e/settings/manual-review/pending/provider-key-native-open.test.ts`): in an isolated Electron profile two manual Providers created from preset templates (ordinary API Key / Coding Plan API Key, non-empty / empty Key). Each Provider's `apiKeyManagementUrl` points to a unique path on a random local port of the test process. The real settings page shows exactly one get entry; before the click the server has no request for the path, after the click the system default browser requests the exact configured path, and the config file bytes are unchanged. No model requests, no real account, no reading of other default-browser pages. A pure custom Provider without templateId shows no such entry per the existing ruling. It needs an interactive desktop with a default browser and is not part of the desktop-less Docker gate; request arrival proves only the native open chain, not the official console login state or mobile shared-host. Exact official template URLs and the with/without Key two-size combinations reuse existing tests. The test opens two local acceptance pages with no account content.

```text
isolated Personal Config single URL -> Settings View -> the only button
    -> IPlatformService -> preload / IPC -> shell.openExternal
    -> system default browser -> unique local canary GET
```
