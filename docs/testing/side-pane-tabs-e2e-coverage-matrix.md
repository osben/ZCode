## Coverage Notes

- SPT-E2E-004 verifies the selected tab shows its close button, an unselected non-hovered tab hides it, hover shows it and a real mouse click closes it without activating that tab; keyboard focus-within also shows the close button, and touch selects first, then closes. It also checks that item-content uses a mask and the text no ellipsis, and that on hover the mask changes while content width and text position stay.
- SPT-E2E-001 also checks the window-drag CSS region of the Side Header in Electron and the no-drag exclusion of tabs and buttons; existing menu and close interactions keep regressing. This assertion does not replace native OS window-move verification.
- Physical width, scroll metrics, DOM containment and visibility are read from the real rendering by Electron WebDriver. Tooltip is verified with a controlled wait window, not provider stream timing. Test expansion conditions use real panel width and opacity; Tooltip uses semantic-node checks to avoid false results from persistently mounted DOM, title prefixes and screen-reader copies.
- Mobile Web touch does not promise a hover Tooltip; its layout shell keeps the existing component tests and is not claimed by this Desktop E2E group.

### SPT-E2E-000 (independent panel layout, platform radius, resize handles)

- Platform expectations: Windows 5px, Sequoia and earlier macOS 6px, Tahoe 26+ and Linux 12px (Web 12px); Windows outer edge / collapsed left gutter 6px with 8px radius; Linux 4px / 12px kept. Three indicator lines: foreground-subtlest/50, along-edge original length, no mask (Windows dual theme verified as sky-500 / sky-400 drag indicators for Sidebar, Side Pane and bottom terminal, length, show/hide and actual dragging); Web keeps the original color, a layout-boundary unit test covers it.
- Resize handles: Sidebar, Side Pane and Terminal handles keep a 4px hit area and a 2px `bg-foreground` indicator, hidden by default and shown on hover/drag; real pointers change Sidebar width, left/right panel widths and conversation/terminal height. The 268px desktop Sidebar width of the settings page is covered by `settings/settings-ui-polish.test.ts`; compact 68px by component tests.
- Per `docs/design/workspace-independent-panels.md`: panel vertical alignment, 4px gap, Header ownership, xl radius, and close-restore width assertions. When expanded, the Side Pane chrome radius token is checked, when collapsed the conversation chrome token; both states check the computed radius (the expanded conversation uses a dynamic variable to avoid false missing-token reports on the independent-panel path). Tab expand/close, resize and drag cases keep covering persistent mounting; the phone branch and Windows/Linux control area are covered by targeted unit tests.
- Toggle-button migration: after expanding the empty state WorkspaceHeader no longer shows the toggle and the Side Header can collapse; SPT-E2E-001 covers collapsing in the Side Header when tabs exist, re-expanding from WorkspaceHeader and keeping the tabs.
- Data chain: `useAppChromeStateAutoUpdate.test.ts` covers platform query -> hook -> radius, verifying macOS 15/26 async results and subscription cleanup (catches a macOS query skipped by a guard on non-macOS CI); it does not replace macOS native visual acceptance. Logo style migration: SPT-E2E-000 verifies the old 28px click area and position, 18px base, 11px static SVG, real hover and click collapse/restore of the Sidebar on Windows/Linux (Windows measured passing; Linux real machine pending, platform conditions covered by component tests).
- Windows / Sequoia real-machine, Linux and phone real-machine visual checks are not run; macOS Tahoe SPT-E2E-000 passes. Final desktop runs: independent panels with real dragging, bottom terminal and dual-theme screenshots (`independent-panels-zai-light.png` / `independent-panels-zai-dark.png` in the run's artifact directory).

### SPT-E2E-007 (plugin menu in empty state and new tab)

- Spec: `packages/ui/test/browser/manual-review/pending/side-pane-plugin-menu.test.mjs`. Empty-state launcher + active new-tab launcher create tabs with the real reducer, covering mouse, Tab/Enter, scope and repeat opens, install/enable, draft / no-host gates and cold load, at 1200px/en-US/light and 390px/zh-CN/dark.
- Loading icon: 8 install/enable cases verify the target entry shows a visible rotating icon and `aria-busy`, other plugins show no progress, and everything clears after success/failure; the same plugin's two surfaces share progress and send the install request once; with reduced-motion preference the icon stays static.
- Concurrent install: the recommended area has no separate global lock and shares the per-plugin busy judgment of the management store with the marketplace; two different plugins can be pending at once, a later failure does not clear the earlier one, and other enabled plugins can be opened during install; duplicate click, same-plugin two surfaces, enable, failure recovery and reduced motion keep covering; the default new-tab and an actively added tab are both covered. The fixture initializes the default new-tab by the current panel owner. Browser E2E 16/16 passed.
- Services come from the fixture; no real Agent, plugin sandbox or phone remote control; stays pending and CI admission is not raised.
