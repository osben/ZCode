# Team Plan E2E Cases

E2E cases that the desktop settings page and usage entry must cover after Team Plan integration. Scope: desktop local workspace only; the interface is a WDIO case-local mock server, and no real BigModel / Z.ai plan API is accessed.

Full history (per-run artifact ids and intermediate failures): `git show 6c0f4203:docs/testing/coding-plan-team-e2e-cases.md`.

## Coverage principles

- Every case has an independent setup, action and assert; "the path was passed through" does not count as coverage.
- Team Plan quota and statistics must use the team project context: `organizationId`, `projectId`, the team header, `type=2`.
- When a personal Coding Plan and a Team Plan coexist, each is shown as an independent Provider and carries its own product data.
- The E2E mock server records business requests so cases can assert whether the enterprise plan list, personal quota, team quota, model usage and tool usage were requested.

## Runner Preflight Contract

- Even when running `wdio run wdio.conf.ts` directly, the Electron package's `path.txt` and the real executable it points to must be verified; the existence of the `node_modules/.bin/electron` wrapper script alone does not mean Electron is installed.
- The WDIO config must first load the desktop/repo `.env.e2e.local` in priority order, then read the Electron install configuration and run the binary preflight, so `ELECTRON_MIRROR`, proxy, certificates and cache directory are passed to both the install subprocess and later E2E processes.
- If the Electron package exists but its binary is missing, the WDIO config runs that package's `install.js` before creating the ChromeDriver session and then re-verifies the real executable. The install wait is bounded: `ZCODE_E2E_ELECTRON_INSTALL_TIMEOUT_MS` overrides the default 5-minute timeout, and after timeout the child process must be terminated.
- When install fails, times out, or still leaves no binary after the install script, the Electron install root cause must be reported directly, with the effective timeout, the redacted mirror address, and the original exception preserved through `cause`; it must not continue and degrade into a vague `Chrome instance exited`.
- The preflight only repairs local E2E dependencies and does not change the desktop `desktop-continuous` session, the mobile `web-remote-replayable` recovery chain or product runtime state.
