# Idle-time Task: Glossary and Domain Model

> **Status: implemented; this file is a code-fact snapshot of 2026-07-22.** The implementation
> includes the `offPeak` domain, `off_peak_tasks`, ticket sync, scheduler/host dispatch, the
> per-turn idle provider, UI and mock. `decisions.md` is the ADR log; early entries such as
> D11/D25/D36 must be read together with their later superseded marks.
>
> Since 2026-08-22, `client/configs.offPeak` only provides the exposure switch; model members and
> static capabilities come from Built-in `builtin:offpeak-idle-plan` and the Effective Model Config.

Sources of truth: `spec.md`, `tech-design.md`, `implementation-notes.md` and the code.

## Glossary

| Term (CN)               | English / code name                         | Current definition                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------------- | ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 闲时任务                | Off-Peak Task / Idle-time task              | A one-shot background task under Automations. A ticket is taken at creation; the session is created at first dispatch; completion enters an irreversible terminal state, running again needs a new task                                                                                                                                                                               |
| 本地任务 ID             | `offPeakTaskId` / server `task_id`          | Stable ID of one logical task, unchanged across tickets and 3h auto-continuation segments                                                                                                                                                                                                                                                                                             |
| 服务端票据 ID           | `serverTicketId` / `ticket_id`              | Ticket ID generated by the server on each take-number. A re-take after expiry overwrites the task row's current value; no ticket history is stored locally                                                                                                                                                                                                                            |
| 取号可用性              | Take-number availability                    | Instant snapshot of `GET /ticket/availability`; creation is allowed only when it returns true; false/loading/unknown/query failure all block, and `POST /ticket` covers the race after the query                                                                                                                                                                                      |
| 取号                    | Take Number                                 | `POST /api/v1/off-peak/ticket {task_id}`. The local task is created only on success; the response carries ticket state, position and a next-poll hint                                                                                                                                                                                                                                 |
| 服务端准入态            | Ticket state                                | `queued / ready / active / expired / settled / not_found`. `ready` is written locally as `schedulable=true`; `active` and local `running` are not written strictly at the same time                                                                                                                                                                                                   |
| 客户端执行态            | Task status                                 | `queued / paused / running / completed / failed / cancelled`. While permission/elicitation waits inside the ordinary session, the aggregate stays `running`; the three terminal states are irreversible                                                                                                                                                                               |
| 闲时队列                | Off-Peak Queue                              | Authoritative position is the server ticket FIFO; the local scheduler has a separate `queued+schedulable` claim queue; user prompts to a busy session are a third message queue. The three are not one global FIFO                                                                                                                                                                    |
| Pause / Continue        | -                                           | Pause only stops local dispatch while the server ticket keeps aging; Continue reuses the ticket if still valid and re-takes a number if expired/not_found/missing                                                                                                                                                                                                                     |
| 自动续跑                | Continuation                                | After messages returns `400/3102`, the same `task_id` re-takes a new ticket, keeps the conversation/session and resumes with a fixed continuation prompt                                                                                                                                                                                                                              |
| 闲时专属 Provider       | `account:{zai\|bigmodel}-offpeak-idle-plan` | Hidden execution-time model source in Built-in Config; never in ordinary model selection. Each automatic turn pins the exact model and injects request access material, without rewriting the session's resident model                                                                                                                                                                |
| Session 常驻模型        | User workspace model                        | First dispatch picks the full `providerId/modelId` by workspace `defaultModel -> lastUsed -> current`. The model bar shows it, not the idle provider; with multiple providers it never guesses by provider alphabetical order                                                                                                                                                         |
| 用户排队消息            | Busy queued prompt                          | A user prompt sent while an automatic turn is busy. At turn terminal the user's resident model is restored before draining, so it uses the user's provider                                                                                                                                                                                                                            |
| Permission approval     | -                                           | Uses only the existing session permission/elicitation chain; Off-Peak aggregation stays `running`. Approval or denial inside the same automatic turn still uses the idle provider; there is no dedicated Review card or duplicate notification                                                                                                                                        |
| 容量等待                | `429/3105 + Retry-After`                    | Special-cased for the idle provider only: a single wait of `min(Retry-After or 60s, 5min)`, abort-aware, unlimited probing, not consuming the ordinary retry budget; the local task still shows `running`                                                                                                                                                                             |
| 灰度开关                | `configs.offPeak`                           | Creation opens only when `enable_offpeak_task=true` and the Built-in offpeak Provider model list is non-empty; the remote only controls exposure and carries no model facts or quota                                                                                                                                                                                                  |
| 创建额度                | Server take-number quota                    | Server-internal `take_number.limit/window` is not sent to the client. The client no longer uses D36's `limit.max_tasks/sliding_window` or local createdAt counting                                                                                                                                                                                                                    |
| 终态核销                | Settle                                      | After a terminal state, call `POST /ticket/:ticket_id/settle` for the current ticket. Network/5xx failures are re-reported from a local outbox; 4xx means there is no ticket left to release                                                                                                                                                                                          |
| History                 | Execution summary                           | A task has 0 or 1 aggregated history row, never expanded per ticket/3h segment; Delete history only writes a `historyDeletedAt` tombstone                                                                                                                                                                                                                                             |
| Keep Awake              | `keepAwakeWhileRunning`                     | Name kept, but the final behavior is a global setting: enabling it starts `prevent-app-suspension` regardless of the active task count; it cannot stop lid-close or user-initiated sleep                                                                                                                                                                                              |
| ~~余额守护 / 算力余额~~ | -                                           | Cut: the client has no money-balance logic and shows no consumed/remaining compute                                                                                                                                                                                                                                                                                                    |
| ~~预计等待 / Est.~~     | -                                           | Cut: the card shows only the server position and computes no ETA                                                                                                                                                                                                                                                                                                                      |
| ~~立即执行 / Run now~~  | -                                           | Cut in v1; to take over manually, cancel the automatic task and continue in an ordinary conversation                                                                                                                                                                                                                                                                                  |
| 会话内创建              | `OffPeakCreate` / `OffPeakList`             | In-conversation entry restored by D49: an agent tool family parallel to the Cron\* siblings, routed by semantics. Create defaults to yolo / last whitelist model / highest reasoning level (intentionally different from the form defaults); an idle automatic turn denies Create while a cron automatic turn allows it (combined play); List is read-only and available everywhere   |
| 绑定会话                | Bound session / `boundSessionId`            | D50: an idle task created in a conversation is bound to and runs in that conversation (aligned with CronCreate `targetTaskId`). `session_id` is written at creation, `conversation_id` is backfilled on first run; if the session is found busy before dispatch it backs off transiently without changing config; Stop cancels it. Form creation still creates an independent session |
| 轮尾卡                  | Turn-tail card                              | Static result card rendered after the assistant body when a reply completes (same pipeline as the cron CronCreateAutomationCard). The idle card = moon icon + title + position snapshot at creation + a 「去到闲时任务」 (go to Idle-time tasks) button; it does not subscribe to later status                                                                                        |

## Relation to scheduled tasks (Automation)

| Aspect      | Scheduled task (Automation)    | Idle-time task                                                                     |
| ----------- | ------------------------------ | ---------------------------------------------------------------------------------- |
| Trigger     | cron expression, periodic      | one-shot; dispatched once the server ticket is ready                               |
| Missed slot | cron misfire may skip          | queued stays and keeps waiting; cron misfire skip is not reused                    |
| Session     | one session per run            | first segment creates one session; later ticket segments resume it                 |
| Queue owner | local cron due time            | server ticket FIFO; local side only claims the ready snapshot                      |
| Provider    | user's resident provider       | session keeps the user provider; automatic turns use the idle provider temporarily |
| Data        | automation table/state machine | separate `off_peak_tasks` table, message types and state machine                   |
| Multi-end   | existing Automation bounds     | mobile `/remote` and desktop remote workspaces hide the idle-time product entry    |

## Two-axis state and sequence

```text
Server ticket:  queued ──► ready ──first messages──► active ──► expired/settled
                       │                                   │
                       └─ batch status writes schedulable  └─ 3102 triggers re-take

Client task:    queued ⇄ paused
                  │
                  └─ scheduler claim → sendPrompt ACK → running → completed/failed/cancelled
                                                      │
                                                      └─ 3102 → queued (same session)

permission / elicitation: the ordinary session waits for the user; the client task stays running.
```

## Invariants and current limitations

- `workspaceKey = workspaceIdentity?.trim() || workspacePath` isolates identity; files/cwd keep using
  `workspacePath`.
- Task, ticket and session are three different lifecycles: one task can change tickets but reuses one
  session.
- Terminal states are irreversible; cancel/failure does not roll back files already written.
- Local `running` is written after the `sendPrompt` ACK and may precede server `active`; the
  429/3105 wait has no separate persisted state.
- `next_poll_at` is a snapshot of the server's suggested time; `OffPeakTaskService` currently syncs
  in batches with one shared timer, not a per-task timer.
- `not_found` is not auto re-taken in background sync; the user's Continue checks and re-takes as
  needed.
- Permission approval does not switch the provider of the current turn; the historical intent of
  D11/D27 was explicitly cut by D44.
