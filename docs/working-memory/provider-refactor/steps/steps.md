This directory records how the Provider architecture entered code in phases: what a phase changes, how it was split,
what was delivered, which deviations appeared, and what remains. The target structure is in
[`../design-v2/design.md`](../design-v2/design.md); historical contradiction rulings are in
[`../design-v2/evidence-and-contradictions.md`](../design-v2/evidence-and-contradictions.md); current-state evidence
is in `../research/`. Research is not target design: new facts found during implementation are first recorded as
evidence, then judged for impact on design-v2 or the current step.

## Maintenance Rules

- Define goals and compatibility boundaries before each phase. Self-directed decisions made while pushing ahead go into
  implementation logs; decisions changing target abstractions, product semantics or public contracts go into Human in
  the Loop, are ruled by humans and synced back to design. Ordinary commit lists and command outputs need not be
  recorded item by item; systemic problems found after merge go into reviews.
- One slice can merge independently, but a phase cannot end with two long-term business semantics. Migration-period
  compatibility logic must have a clear position and an exit condition.
- Update the phase document, Roadmap and Working Memory entry after a phase completes.
