## B3: Default Selection And Distribution

- Source reads full snapshots from the unique Personal Repository and verifies disk content hashes; legal-empty-but-unshipped is distinguished from bad files. Target locks compare entire Personal content; full replace and full rollback; no dual-writing of default selections. Envelopes dropped `sourceRevision`/independent `configuredDefault`; results use `configRevision`. Both entry points reuse the formal codecs.
- Failure rollback restores A; if a concurrent writer already wrote a different C, C is retained and `rollback_failed` is reported. Providers and defaults are under the same CAS protection. Credentials/settings keep their original domain rollbacks — no global transaction system.
- Default `providerOrder` is never fabricated as `[]` from `undefined`; post-write snapshots use the codec-normalized content, so re-reading after save never yields a different revision. Verified with two real Node child processes writing 20 times each after IPC barriers — both Provider and default selections retained.

## B4: Paths And Source Revisions

File locks and common atomic writes are reused — no separate IO or sync system.
- Source revision includes the active file's absolute path identity; the active path itself contains the normalized Endpoint. Host injects the same active path into Workers, so both get the same revision.
