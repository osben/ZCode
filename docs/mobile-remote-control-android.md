# Android Remote Control Shell

`packages/android` is the Android shell for ZCode mobile remote control. Version one does not
rewrite the ZCode Agent, relay, or RPC protocol; the native shell hosts the existing `/remote`
mobile web page.

## Entry points

- Paste or share a `https://zcode.z.ai/remote?...` link.
- Scan the remote-control QR code generated by the desktop app.
- Open via `zcode://remote?...` deep link.
- The home screen keeps the last 5 successfully opened remote links, available after app restart.
  The list shows only device name, host and time; full links live in app-private
  `SharedPreferences`.

Production builds only open `https://zcode.z.ai/remote`. Debug builds additionally allow localhost
and LAN `/remote` for on-device debugging of a local Vite page.

## QR scanning

Scanning uses CameraX preview and ML Kit Barcode Scanning. The scanner reads QR Code only; scanned
content still goes through `RemoteControlUrlPolicy` — invalid links never reach the WebView.

## Background stability

With a remote page open, the app starts a foreground service and keeps the screen on. The service
only lowers the chance Android reclaims the process or restricts the network; it is not a business
source of truth. Disconnect and recovery still rely on the existing web remote
`web-remote-replayable` semantics, bridge rebuild and task snapshot alignment.

The Android app never creates its own Agent runtime, local host, or SSH/WSL/Docker session; mobile
can only attach to a host already present in a desktop window.
