# Settings Usage Stats

Add a `Usage` section to Settings to show rough usage statistics aggregated from local session snapshots.

## Data Source

- Add a host-side `usage-stats` RPC service to scan task snapshots under `~/.zcode/v2/sessions/**`.
- The UI does not read the disk directly; it calls the service through `useUsageStats()`.
- For historical data without a usage field, the reader falls back to character counts from `message.content + thought` and `task.meta.model`.

## Estimation Method

- Estimate tokens consistently as `character count ÷ 3`; define the divisor in `ESTIMATED_TOKEN_CHAR_DIVISOR`.
- Persist additional fields for new messages:
  - `message.model`
  - `message.characterCount`
- Store the original character count rather than a token estimate so historical data can be recalculated if the divisor changes.

## Current Display

- **Section corner radius:** Use `rounded-xl` consistently for overview metric cards, daily Token trends, model-usage distribution, Coding Plan quota cards, and the shared empty state to keep the main statistics modules at a consistent visual hierarchy.
- **Token activity:** Provide separate daily, weekly, and cumulative ranges. Daily shows values by day, weekly shows the total by week, and cumulative shows total Tokens through the current week. Use the same pill tabs as the Hooks range switcher, sized and typed to match task tabs (outer `h-7`, trigger `h-6`, `text-ui-sm`). The grid always shows the most recent 52 calendar weeks, with Sunday as the first row. Divide its 52 columns evenly using `minmax(0, 1fr)` without horizontal scrolling, and use `gap-0.5` for horizontal and vertical spacing. Anchor month labels to the week column containing the first day of each month; show at most the last 12 valid month labels. Keep grid space for earlier starting months but leave their labels blank, so the current annual cycle runs from September last year through August this year, then advances naturally by year. In weekly and cumulative views, hovering any cell highlights its entire column, and the tooltip anchors to that column. Use a two-row tooltip: dates/week range on the first line, Token count and message-turn count on the second; use `rounded-xl` for its container.
- **Daily Token trend chart:** Show the last 7 days by default, with an option for the last 30 days. Fill missing dates consecutively before plotting estimated Tokens as a line. Set the Y-axis maximum from the peak individual point among the model lines actually shown; do not use the sum across all models for the same day or include hidden models, which would compress non-stacked lines. Use localized compact Token units in both the tooltip total and each Model value (Chinese ten-thousand/hundred-million units, English K/M/B, with `tokens`) so model details are not long, unitless numbers. Use monospaced type for tooltip numbers to align them; render `tokens` / `tokens/s` units in UI Sans with subdued color, and do not inherit `font-mono`. The time-range tabs below use pill styling sized to match task tabs (outer `h-7`, trigger `h-6`, `text-ui-sm`).
- **Coding Plan system health:** Always show average peak-period Decode speed over the last 7 days for Max&Pro / Lite. Do not provide a time-range filter or request/return 30-day health data; mark “Last 7 days” as read-only copy on the right side of the title.
- **Coding Plan usage trends:** Use grouped bar charts consistently for the last 7/30 days and Model/Tool dimensions. For both new and old data, show selectable Model / Tool lists; select at most 3 items at once and keep at least 1 selected. In the Models view, add the `tokens` unit to Token usage in the top Total, Model checkboxes, Tooltip Total, and Tooltip details. In credits mode, add the localized “credits” unit in all four places. Keep numbers monospaced and units in UI Sans. Do not add a Token or credits unit to Tool call counts. Use bar charts for legacy data containing only Tokens/call counts too; do not fall back to line charts. Show the credits/usage-metric switch only when credits data exists. Reserve line charts for the fixed 7-day system-health view below.
- **Model usage chart:** Aggregate estimated tokens by model and show their proportions in a pie chart. Combine into “Other models” when there are more than six segments. Reuse trend-chart `--color-usage-chart-*` tokens. On mobile, retain a 224px chart height and stack vertically. On desktop, give the chart and details equal widths, increase chart height to 256px and maximum width to 288px, and vertically center it relative to the details on the right so the donut uses available space without growing indefinitely on wide screens.
- **App Usage time range (P2):** The range control offers `Last 7 days`, `Last 30 days`, `Last 90 days`, `Last year`, `All time`, and `Custom`, as pill tabs sized like the other usage tabs; on narrow widths the tab strip scrolls horizontally instead of wrapping. `7d` / `30d` keep sending the legacy `range` only (rolling window, byte-identical request). `90d` / `1y` / `Custom` send an additive `window` of whole local calendar days (inclusive, in the browser time zone, ending today for presets) with `range: "all"`; `All time` sends `range: "all"` with no window. Custom shows two native date inputs (`max` = today); the request is sent only when the pair is valid (from <= to, not in the future, at most 800 days); an invalid pair shows an inline `text-destructive` message and keeps the last valid data on screen. History before the usage rollup was first created does not exist; ranges that reach beyond the oldest recorded day simply show zero days.
- **Compare with previous period (P2):** A switch (hidden for `All time`) asks the host for the immediately preceding period of equal length. The daily trend chart then draws the previous period's daily total as a dashed, subdued line aligned day by day (tooltip label `Previous period`), and each detail tile shows a neutral delta (`▲ 12%` / `▼ 8%` / `0%`; no success/destructive colors, since up or down is not inherently good or bad). A host that does not return `previous` simply shows no comparison. A host that predates the `window` field rejects the request with a strict-schema error; the panel keeps the last data and shows the standard error notice.
- **Trend granularity (P2):** For windows longer than 14 days a `Day / Week / Month` pill group re-buckets the daily series client-side (weeks start on Sunday, matching the heatmap; month buckets start on the 1st). Default is automatic: up to 45 days daily, up to 200 days weekly, otherwise monthly. The previous-period line is bucketed with the same groups.
- **App Usage filters (P3):** Under the range controls, a filter bar offers multi-select menus for `Models`, `Providers`, `Source`, and `Workspaces` (pill buttons with a selection count, popover with checkbox rows, per-menu `Clear`, and a `Clear filters` action). Options come from the `facets` of the unfiltered all-time snapshot, so choices never disappear while a filter is active; the bar is hidden when the host omits `facets` (no rollup). Selected filters are sent as the additive `filters` request field to the main snapshot only; the all-time snapshot, summary strip, and heatmap stay unfiltered. Model / provider / source filters narrow token and model data (trend, pie, tiles for tokens, cache, TTFT, model errors); turns, sessions, and tools follow only the workspace filter, and a subdued note says so while a token-scoped filter is active. Workspace options are session directories labeled by folder name (full path in the tooltip); the empty key is `Unknown workspace`. Unknown model ids render as `Unknown model`; query sources `main_turn` / `subagent` / `workflow_child` are translated, others show the raw value.
- **Heatmap day drill-down (P3):** In the daily Token Activity view, a cell with usage is a button (`role="button"`, keyboard Enter / Space, `aria-label` = date). Selecting it switches the range to `Custom` with that single day as both start and end, keeping active filters and the compare switch. Weekly and cumulative views are not selectable.
- **Activity by hour (P4):** When the host supports extras (the all-time snapshot carries `facets`), the main request adds `include: ["hourly", "sessions"]`. A `rounded-xl` "Activity by hour" section draws a 7 x 24 grid (rows = weekdays starting Sunday, columns = hours 00-23 in the browser time zone) from `hourlyTokens`, colored with the existing `--color-usage-heatmap-*` levels (ratio to the busiest cell, same thresholds as the daily heatmap), with hour labels at 00 / 06 / 12 / 18 and a caption naming the busiest weekday and hour. Each cell has a text title (`Tue 15:00 - 1.2M tokens`). The section is hidden when `hourlyTokens` is absent or all zero.
- **Busiest sessions (P4):** A table of up to 10 sessions of the selected window ranked by tokens: title (`Untitled session` when the session row no longer exists), workspace folder name, tokens, turns, and total completed time. Rows come from `topSessions`; the section is hidden when empty. Session token totals come from per-turn usage, so buckets rolled up before this column existed show 0 and are omitted.
- **Export (P4):** Two footer buttons export what is on screen: `Export CSV` (long format `date, model, tokens` for the visible range, one row per day and model with tokens) and `Export JSON` (the selected snapshot without the heatmap, plus the active query). Desktop uses `IPlatformService.saveFile` (native save dialog); Web falls back to a Blob download. CSV text cells that start with `=`, `+`, `-`, or `@` are prefixed with `'` to defuse spreadsheet formula injection. File names are `zcode-usage-<from>_<to>.csv|json`.
- **App Usage details (selected range):** Below the daily trend chart, show a `rounded-xl` "Details" group of 8 metric tiles for the selected 7d / 30d range, read only from the existing `AppUsageSnapshot.summary` (no new request, field, or storage): input tokens, output tokens (helper: reasoning tokens, only when > 0), cache hit rate (helper: cache-read tokens), average turn duration, average time to first token, tool calls, tool error rate, model error rate. Do not re-add the sessions / messages / active-days / favorite-model cards removed earlier. Tiles reuse `UsageMetricCard`; layout is 2 columns on mobile and 4 on desktop. Null averages render `--`. Durations use locale-aware `Intl` units (ms / s / min / h), never the minute-floored lifetime formatter. Hide the group when the range has no model requests and no tool calls.
- **App Usage tools table:** Below the model pie chart, list tools from `AppUsageSnapshot.tools` sorted by call count (server order): tool name (monospace, truncated), calls, errors with error rate (error color only when > 0), average duration. Show the top 8 and a "Show all N" / "Show less" toggle when there are more. Hide the section when `tools` is empty. Tool names are raw identifiers and are not translated.
- **Summary metrics:** estimated tokens, number of sessions, active days, most-used model, longest session, and consecutive active days.
