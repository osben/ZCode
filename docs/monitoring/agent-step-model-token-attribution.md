# Agent Step Real Model and Token Attribution

## Scope

This release only corrects the existing `agent_step` within the message lifecycle:

- Step uses the actual requested model/provider/hostname, not shared fields after the last message request is overwritten.
- Provider's single complete request usage is attributed to one step, ensuring step tokens can be summed.
- Foreground Subagent usage aggregated to the corresponding parent `Agent` tool step.
- Foreground Subagent's child `thought/text` does not directly generate step; related steps come from parent
  session's Agent/tool mirror lifecycle.
- Background Subagent's child tool continues to report one by one; additionally, a `Agent` step is reported
  in child terminal state, carrying the accumulated usage of the child's completed model request, reusing
  foreground's builder field. Does not consume child `thought/text` to generate reasoning/generation.
- No new independent `message_completion` for background child.
- Main `message_completion` increases `agent_composition`: `main_only` indicates this round consumed
  no Subagent results; `main_plus_fg` indicates only foreground results; `main_plus_bg` indicates
  only background results; `main_plus_fg_bg` indicates both have results.

```text
User message M1
  |
  +-- Main request R1(model=A)
  |     +-- reasoning step   model=A, tokens=0
  |     `-- generation step  model=A, tokens=usage(R1)
  |
  +-- Agent tool step         model=B, tokens=sum(child requests), agent_id=child
  |     |
  |     +-- child request C1  model=B
  |     `-- mirrored WebFetch model=B, tokens=0, agent_id=child
  |
  `-- Main request R2(model=A)
        `-- generation step  model=A, tokens=usage(R2)

background child B
  +-- child thought/text     -> does not directly generate agent_step
  +-- child tool lifecycle   -> tool_call step, model=B, tokens=0, agent_id=child
  `-- First terminal/stopped  -> Agent step, tokens=sum(received child requests)，no usage defaults to 0

main wake round from background notification
  `-- main message_completion -> agent_composition=main_plus_bg
```

## Attribution Rules

1. All steps generated by the same request freeze the real model identity of that request.
2. Complete request usage only written to the last model output step of that request.
3. Earlier-finishing reasoning steps and pure tool execution steps within the same request keep token as `0`.
4. Foreground child's model and accumulated usage incrementally written to parent `Agent` step; should not wait
   for `SubagentStopped` to first fill.
5. Mirrored child tools keep independent `tool_call_id` and token `0`; they use the same
   `agent_id` as the parent `Agent` step, and model uses the child's real request model.
6. Background child's usage is attributed only to its own `Agent` step and never refills the completed parent
   turn. Child tools keep token `0`; the Agent step is appended on the first child terminal or `SubagentStopped`,
   using the child-local next `loop_index`. Its `tool_call_id` is `tool_subagent_<agentId>_<parentToolCallId>`;
   the Agent launch step in the parent session only describes the launch action, and accumulated usage is not a
   snapshot of each tool end time. An active child receiving any terminal state, even without usage, still
   reports the Agent step with state, errors and known model; token/request count default to `0` and no
   requestId or usage scope is fabricated. This matches the foreground exception closure's known-usage snapshot:
   no duplicate summary and no top-up after closure.
7. Background mirror's tool/permission fact must carry `background=true`, filtered before entering main prompt
   telemetry, avoiding duplicate counting of same child tool or permission wait.
8. Background child's report uses parent session、`sourceCommandId`、`parentToolCallId` and
   `childSessionId` to establish attribution; no guessing report when necessary attribution fields missing.
9. `message_completion.agent_composition` only describes the current main turn's Agent composition:
   foreground child sets position at result closure; background notification dequeued and position set
   when received in independent wake, or in active-loop legitimate merge position. Failure/cancel preserves
   already-consumed facts; cannot set position just because child only spawned/stopped.

## Facts and Attribution Chain

```text
model_request_started/completed + ModelComplete(usage)
          |
          v
normalizer: requestId + model identity + usage
          |
          +-- main session  ------> current model-output step
          |
          `-- child session ------> childSessionId accumulate
                                      |
SubagentSpawned(childSessionId, parentToolCallId, agentId)
                                      |
                                      +--> parent Agent step
                                      `--> mirrored child tool`
```

Authoritative field sources:

| Field             | Fact source                                                              |
| ----------------- | ------------------------------------------------------------------------ |
| `model_name`      | `ModelNetworkStatus.modelId`, reused `<provider>/<model>` reporting code |
| `model_provider`  | `ModelNetworkStatus.providerId`                                          |
| `provider_name`   | `ModelNetworkStatus.baseURL` clipped by hostname                         |
| token usage       | `ModelComplete.usage` adjacent to this completed request                 |
| child attribution | `SubagentSpawned.childSessionId + parentToolCallId + agentId`            |

`ModelComplete` has no independent requestId, therefore normalizer only correlates the most recently completed
request within the same session, same `querySource`; if uncorrelated, it is still usable for the message completion total,
but cannot fabricate step model attribution.

## `agent_step` Fields

Reserve existing fields and supplement:

| Field                      | Scope                                                                                                                                  |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `model_request_id`         | Real model request to which usage belongs; empty step not owning tokens                                                                |
| `model_request_count`      | Real request count aggregated in current step; ordinary main Agent request as `1`, subagent Agent step may be > `1`                    |
| `token_usage_scope`        | Main Agent single request as `model_request`; foreground/background child lifecycle aggregated as `subagent_requests`; otherwise empty |
| `input_tokens`             | Request usage input                                                                                                                    |
| `output_tokens`            | Request usage output                                                                                                                   |
| `reasoning_tokens`         | Request usage reasoning                                                                                                                |
| `cached_tokens`            | Request usage cache read, retain old field name                                                                                        |
| `cache_write_input_tokens` | Request usage cache write                                                                                                              |
| `total_tokens`             | Request usage total                                                                                                                    |
| `agent_id`                 | Stable agent identifier for Subagent; parent `Agent` step, foreground mirror tool and background child tool take its own child value   |
| `agent_role`               | Subagent step's source role: `foreground subagent` or `background subagent`; main agent step does not fill                             |
| `tool_call_id`             | foreground mirror uses Runtime-generated scoped ID; background child uses `tool_subagent_<agentId>_<childToolCallId>`                  |

## `message_completion.agent_composition`

This field indicates the Agent composition of the current main turn:

| Value             | Meaning                                                                          |
| ----------------- | -------------------------------------------------------------------------------- |
| `main_only`       | No foreground or background Subagent results                                     |
| `main_plus_fg`    | Only foreground Subagent results                                                 |
| `main_plus_bg`    | Only background Subagent results, and notification has entered current main turn |
| `main_plus_fg_bg` | Both foreground and background results have                                      |

background child finishing itself does not set this field; its synthesis notification is dequeued and triggers
independent main turn, or in current active-loop actual merge position. Bash notifications do not count as Subagent results.

Statistics keep the current flat request model facts and the ModelSelection execution boundary: they do not read
Provider configuration to guess the model, nor re-resolve the selection to replace an already executed model.

All numeric fields continue to use string encoding. Steps without real usage must write `0`, cannot estimate.

## Timing and Exceptions

- Request status, usage fact and step all go by `eventId/requestId` dedup; replay cannot cause duplicate accumulation.
- Model identity frozen at step creation, subsequent main Agent or child request cannot overwrite historical step.
- When main model directly returns `tool_use` and has no body, add a zero-duration generation step to accommodate main request usage;
  must not mix main model usage into subsequent tool step.

```text
child request started(B) -> child usage -> parent Agent failed -> SubagentStopped
          |                    |
          `-------- Incremental refill parent Agent(model=B, usage=child) -------->
```

- Foreground runner's success, failure, activity timeout and abort all uniformly output `SubagentStopped`;
  outer `Agent` tool has separate timeout. Both real terminal states: whoever arrives first uses current known child usage
  to close, cannot add telemetry's own grace timer. After parent `turn.terminal` arrives must first report remaining `agent_step`,
  then report `message_completion`.

```text
SubagentStopped ─┐
                 ├─ first terminal wins -> Agent step -> remaining normal steps -> message_completion
Agent timeout ───┘
```

- `sendQueuedNow` terminates current turn first, then starts next turn with queue item original `sourceCommandId`. If previous
  message's terminal waiting for foreground Subagent closure, next message's `turn.started` and subsequent facts must be
  stored by command; previous message `agent_step -> message_completion` completed before next message can activate.
  This barrier only exists in real deferred terminal window, cannot be extended into generic message serializer.

```text
message A turn.terminal -> wait SubagentStopped -> A agent_step -> A message_completion
                                 |
message B turn.started/facts ----+---- buffer ----------> activate/replay B
```

- As long as child has sent real `model_request_started`, parent Agent tool step uses child model; even if request has no usage
  cannot roll back to parent message model. Failure or cancel only preserves child usage completed before terminal, no estimation.
- After `SubagentStopped`, still preserves child association to message closure to handle late mirror tool closure.
- renderer reload/recovery does not fabricate historical embeds, maintain existing live-only boundary.
- desktop continuous & web remote replayable share no-text facts schema; existing product rules only allow trusted
  desktop continuous attachment to consume workspace telemetry, recovery replay does not re-report.

Background child's `model.request.status(started)` freezes tool model; `usage.delta` aggregated by requestId
after dedup. `turn.terminal` / `SubagentStopped` share a one-time Agent summary calculation, taking first closure's received
usage; no usage still reported, token defaults `0`. Stopped does not equal child exit, therefore after stopped closure
only preserves started tools and their permission wait state for gradual tool closure reporting; all tool closures or
child terminal arrival cleans up, no longer guesses clean-up moment based on presence/absence of model request/usage.

- Only consumes existing Runtime events: normalizer retains existing `SubagentStopped.error` as `errorMessage`.
  No new Runtime event, does not change execution, cancel, notification, main wake or foreground behavior; does not add timer,
  does not synthesize child completion. Exception closure's late-arrival usage not counted in already-reported summary, does not promise
  complete tail consumption.

## Main Turn ID

Ordinary user turn and independent background notification wake share UUID v7 generator. Each wake batch generates its own
new `inputId`, reported along `TurnStarted.inputId -> sourceCommandId -> message_id`, shared by step/completion in same round,
not reusing original user turn ID. Persistent synthetic `msg_*` ID maintains original purpose, not to be reused by normalizer
as telemetry inputId. Active-loop consumption does not create new round or new telemetry ID.

## Verification

Each new draft of background lifecycle E2E must explicitly select full access (yolo) before submission; suite opening once cannot
replace subsequent draft pre-initialization. BG13's running log has proven that default build may make child Bash etc. require approval,
cannot mistake permission wait for notification or statistical loss; product approval logic does not therefore change.

At least covers:

1. Single request reasoning + generation: two steps are real model requests, usage appears only once.
2. Main model A → foreground Subagent model B → main model A: three-step model and token do not mutually overwrite.
3. Same request usage repeated arrival: only accumulate once.
4. Background Subagent: child thought/text does not produce step; child tool lifecycle produces tool step with same format
   as foreground mirror, token `0`. After child terminal, Agent step exclusively accumulates usage, also with child `agent_id` and
   `agent_role`; final HTTP report verifies request count, total tokens and order.
5. Provider hostname only reports hostname, does not leak URL path/query/credentials.
6. Child cancel and parent `Agent` step pre-failure: still preserves completed child usage and real model.
7. Mirrored WebFetch: same `agent_id` as parent `Agent` step, model is child model, token `0`.
8. Active background child without usage: success/failure/cancel still produces one zero-token Agent step; distinguish
   from request count/scope. Covers only stopped, with/without usage, two terminal orders, duplicate terminal and stopped
   late tool; summary reported once only, error text retained, no independent `message_completion`, no late-usage top-up, not clean up
   started tool closure upon cleanup.
9. Background child's multiple tool step's `loop_index` increments within child, parallel child starts from `1` independently.
10. Ordinary reasoning, generation, tool_call and foreground `Agent` step coexist in one message; all retained, `agent_step_cnt`
    matches actual reported count.
11. `message_completion.duration_ms` maintains user-visible wall clock scope, i.e. `turn terminal - sendTime`, naturally covering
    this round's main Agent, foreground Subagent, tool wait and final generation.
12. `message_completion.agent_composition` calculated only when main completion generated, does not change `agent_step` quantity
    or background child independent report.
13. When previous message waits for foreground Subagent closure and clicks "queue now": previous message uses its own
    `request_time`, real wall clock duration and step count completes first, then next message uses original
    `sourceCommandId` to independently report step and completion.

## Postscript: Third Source — Dynamic Workflow Sub-agent

Rules see `apps/zcode-cli/packages/dynamic-workflow/docs/execution-engine.md` "Token telemetry for subagents". Differences from
the first two sources are only three points:

- Registering fact is not `subagent.lifecycle`, but derived from parent session `DynamicWorkflowRunProgress` as
  `workflow.lifecycle` (`actor-spawned` / `run-settled`); attribution key is `runId + childSessionId`,
  `message_id` is run's `run-launched.inputId` (not any `Agent` tool call).
- Terminal state is **run settlement** rather than child's own `turn.terminal`: a sub-agent session can accommodate multiple asks,
  each ask is a step; summary step only sent at `run-settled` for each sub-agent of that run.
- `agent_role = "workflow subagent"`, also with `workflow_run_id` / `child_session_id` /
  `workflow_tool_call_id`; `token_usage_scope` still reuses `subagent_requests`.

All other rules (tool step token `0`, requestId dedup, no top-up after terminal, live-only, no usage also zero-value summary)
verbatim along.
