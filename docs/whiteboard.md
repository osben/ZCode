# Whiteboard

The right shared pane gains a `Whiteboard` tab, using the same side pane tabs as Browser, Review and Treemapping.

## Behavior

- A new whiteboard is isolated by the current workspace; the workspace key is `workspaceIdentity?.trim() || workspacePath`.
- The default name is generated by the current language, for example `画板 1` / `Whiteboard 1`, and is not duplicated within one workspace.
- Whiteboard content is saved as stroke data containing tool, color, thickness and points; closing the tab does not delete the whiteboard.
- The chat composer's `@` panel lists the current workspace's whiteboards. Only when the user selects a whiteboard are the current strokes exported as PNG and added to the composer as an existing `image` attachment.
- The whiteboard pane toolbar offers an "Add to conversation" button; clicking it exports the current whiteboard as PNG and adds it to the current chat composer's attachment area. The button only fires a UI-internal event; the actual export, attachment limit check, draft and focus restoration are still handled uniformly by the composer.

## Boundaries

- The whiteboard is a UI-layer capability and adds no Agent runtime, relay, main process or server state.
- Image sending reuses the existing `ZCodePromptAttachment.kind === "image"` path; when the Agent does not support images, the existing error handling is kept.
- Web remote control and desktop both go through the same composer attachment chain and do not change the task stream boundary of desktop continuous and web remote replayable.
