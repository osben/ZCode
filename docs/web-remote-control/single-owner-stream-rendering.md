# Single Owner Stream Rendering

> Status: currently describes only non-owner content filtering under replayable subscriptions. The desktop
> `continuous` subscription still consumes direct dynamic stream events. The mobile Web remote control
> `replayable` subscription needs this strategy to reduce the risk of disconnection recovery interleaving with
> snapshot alignment.

## Background

After sharing the host process, the desktop and mobile clients are still independent renderers. The mobile
browser may sit in the background, disconnect, or be discarded by the system for a long time. If all renderers
consume the same streaming chunks directly, disconnection recovery can intersect with snapshot alignment and
produce duplicate tail chunks or runtime forks.

## Rule

Each prompt is generated by the sending renderer and passes `clientId`. The host process stays the sole ZCode
runtime and persistence fact source; `task_stream_mirror_batch` carries `ownerClientId`. Replayable
subscriptions filter ordinary content-class batches by the subscribing `clientId`:

- The sending end matching `ownerClientId` receives complete streaming `ops` and renders body text, tools,
  permissions and other fine-grained state in real time.
- Other replayable renderers may filter ordinary body text, thought and tool chunks to avoid redundant rendering.
- `permission_request`, `elicitation_request`, their responses, `task_complete` / `task_error` and snapshot
  invalidation must not be swallowed by owner-only content filtering; they must be visible to online clients of
  the same task or trigger snapshot alignment.
- Final messages, file changes and task metadata are still aligned through `getTaskSnapshot()`.

## Stability boundary

Observer renderers no longer repeatedly consume intermediate chunks because of mobile disconnect, reconnect or
task switching. If the sender is the mobile client, its real-time view may still be lost, but the host process
keeps consuming the provider stream and persists the final snapshot; after the mobile recovers, the snapshot is
the authority.

## UI behavior

The desktop continuous client keeps real-time body-text rendering through the direct stream.
