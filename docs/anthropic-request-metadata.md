# Anthropic request device and session metadata

## Status

- This document is the source-of-truth spec for zcode-cli Anthropic model request `metadata.user_id`.
- Device identity reuses `deviceMid` from `{dataBaseDir}/.zcode/v2/telemetry-state.json`.
- Assembly and injection of the metadata happen only in zcode-cli; Desktop, Host, Web, and the app-agent protocol are unchanged.

## Request contract

Every Anthropic-format request issued by the zcode-cli AI SDK adapter must carry:

```json
{
  "metadata": {
    "user_id": "{\"device_id\":\"7f1431f0-53e8-41c1-9cf9-22d11aa51d6a\",\"account_uuid\":\"\",\"session_id\":\"2d480878-38af-4bae-a54f-096e2fb0f4d7\"}"
  }
}
```

`metadata.user_id` is a JSON string with these fields:

- `device_id`: the current Agent environment's persisted `deviceMid`, used as the raw UUID without conversion to another ID.
- `account_uuid`: always an empty string today; zcode-cli has no Anthropic OAuth account UUID.
- `session_id`: the current model request's session id, reusing the `x-session-id` external normalization that strips the `sess_` and `subagent_agent_` internal prefixes; empty string when the underlying call has no session context.

Request-level metadata must override any static `anthropic.metadata.userId` in provider config, so static config cannot carry a stale device or session identity into a new request. All other Anthropic provider options (for example `thinking`, `effort`) stay unchanged.

## DeviceMid ownership

Desktop, remote zcode-server, and zcode-cli each have their own "ensure deviceMid exists" entry point but read and write the same state:

```text
Desktop ensure (sync) ──────────┐
remote server ensure (async at startup) ├─> {dataBaseDir}/.zcode/v2/telemetry-state.json.deviceMid
CLI ensure (async) ─────────────┘                          │
                                                  v
                                  zcode-cli Anthropic metadata.device_id
```

- Local Desktop usually generates `deviceMid` before the Agent starts; zcode-cli reads and consumes the same value.
- Standalone CLI or SSH/WSL/Docker Agents do not depend on Desktop: the CLI generates and persists it itself, and the remote `zcode-server` also ensures `deviceMid` in the same file at startup, so the Agent reads the same value.
- The CLI uses the same `createUuid()` format as Desktop/telemetry and preserves other fields in the state file.
- The CLI coordinates concurrent reads/writes with `telemetry-state.lock` and caches one ensure promise per state file in-process.
- File IO or lock failures must not block model requests: return and cache a UUID generated by the current process, and retry persistence on the next process start.
- `ZCODE_DATA_BASE_DIR` selects the actual data root; without it, fall back to the current Agent environment's home directory.
- Model I/O debug logs keep the metadata structure but replace the whole `user_id` with `[REDACTED]`; device identity is never written to disk.

So a local Desktop and its Agents share one device identity; a remote Agent has an independent identity in the remote data directory. Mobile `/remote` uses the connected Agent's identity through shared-host attachment and generates no mobile-side identity.

## Request path and boundaries

```text
ModelStatusContext.sessionId ──normalize────────────────┐
CLI ensureDeviceMid() ────────read/generate─────────────┼─> JSON.stringify(user_id)
account_uuid ─────────────────fixed empty string────────┘
                                                    │
                                                    v
                         providerOptions.anthropic.metadata.userId
                                                    │
                                                    v
                                  AI SDK Anthropic request metadata.user_id
```

- `generateText`, `streamText`, compact, title, sub-agents, tool secondary models, and adapter retry share the same model request options path.
- Injection happens only for `providerKind === "anthropic"`; OpenAI, OpenAI-compatible, gateway, and custom transports add no such metadata.
- A retry may generate a new `x-request-id`, but `device_id` and `session_id` stay unchanged for the same logical request.
- The field is for upstream request attribution only; it is not a local auth, session routing, or workspace isolation key.

## Impact Brief

| Field            | Value                                                                                                                |
| ---------------- | -------------------------------------------------------------------------------------------------------------------- |
| Developer intent | Anthropic requests carry the device identity shared with Desktop/telemetry plus the current session                  |
| Capability       | Anthropic request attribution metadata                                                                               |
| Change layer     | `commit-effect`, `persistence`                                                                                       |
| Operating mode   | `planning`                                                                                                           |
| Primary seeds    | `ensureDesktopDeviceMidSync`, `createTelemetryCore`, `runGenerateText`, `runStreamText`, `createGenerateTextOptions` |
| Out of scope     | UI, app services request headers, protocol, conversation/replay state, non-Anthropic providers                       |

UI Surface Matrix: no UI entry. The authoritative persistence is `telemetry-state.json.deviceMid` on the Agent's host; the zcode-cli model adapter is the metadata commit sink.

| Rank           | Relationship                                  | Reason                                                |
| -------------- | --------------------------------------------- | ----------------------------------------------------- |
| must-inspect   | CLI deviceMid ensure → telemetry state        | reuse the same field, keep other telemetry state      |
| must-inspect   | model runner → Anthropic provider options     | generate/stream and retry share one injection path    |
| should-inspect | session attribution header → metadata session | header and body must not use two prefix rule sets     |
| conditional    | local Agent → remote Agent data root          | device identity follows the actual Agent environment  |
| invariant-only | non-Anthropic providers                       | no new metadata, no provider option changes           |
| invariant-only | desktop continuous / mobile replayable        | message flow, snapshot, and recovery bounds unchanged |

Graph drift: the existing feature graph does not declare Anthropic request metadata or shared deviceMid persistence; this capability, its service, persistence, and semantic edges are to be added there.

## Accepted Cases

| Case  | Setup                                     | Action                              | Assertions                                               |
| ----- | ----------------------------------------- | ----------------------------------- | -------------------------------------------------------- |
| ARM01 | state already has `deviceMid`             | Anthropic generate                  | body uses the existing value and normalized session      |
| ARM02 | state lacks `deviceMid`                   | standalone/remote CLI first request | CLI generates a UUID, preserves other state, persists    |
| ARM03 | concurrent first requests                 | Anthropic generate/stream           | the same state file yields and consumes one persisted ID |
| ARM04 | static Anthropic metadata plus `thinking` | request issued                      | dynamic userId overrides static; other options kept      |
| ARM05 | OpenAI-compatible provider                | request issued                      | no Anthropic metadata injected                           |
| ARM06 | state IO failure                          | Anthropic retry                     | request continues; same fallback ID within the process   |

No conversation case catalog, coverage matrix, or E2E handoff required; adapter unit tests and real Anthropic wire body tests are the evidence.
