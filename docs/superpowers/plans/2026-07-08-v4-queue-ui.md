# V4 Queue UI

> Historical implementation plan (2026-07-08), implemented and archived. Kept for the queue
> panel interaction contract not covered by `docs/ui/chat-message-queue.md`.

**Goal:** Align the v4 queue panel with the z-code-2 queue UI: queue edit extracts the item
into the composer, and drag reorder drives CLI projection state.

## Contract

- Queue authority stays in the CLI projection (`snapshot.queue.items`); the renderer holds no
  local queue order state. All mutations go through v4 commands (`sendQueuedNow`,
  `deleteQueueItem`, reorder).
- Drag reorder (`@dnd-kit`): on drag end the UI computes a `beforeQueueItemId` anchor via
  `resolveV4QueueReorderAnchor(items, activeId, overId)` — downward moves use the item after
  `overId`, tail moves use `null` — and sends the reorder command; local order is never
  mutated. `TurnSteerReordered` updates the projection.
- Queue edit ("撤回编辑" / withdraw-edit): `SessionPane` looks up the item text from the
  current projection, sends `deleteQueueItem`, and only for accepted/noop ACKs fills the
  composer through `ConversationComposer`'s
  `externalTextInsertRequest?: { requestId: number; text: string }` — each request applied
  once via `inputApiRef.current.setText()`, local text state updated, draft persisted,
  editor focused.
- Visible copy: the item action shows `立即`, not `立即发送`; the old `上移` (move-up) button
  copy is gone — reorder is drag-only.
- Structural anchors: `packages/ui/src/v4/ConversationQueuePanel.tsx` (`data-testid="v4-queue"`,
  `data-queue-item-id`, `data-v4-queue-drag-handle`), `packages/ui/src/v4/SessionPane.tsx`,
  `packages/ui/src/v4/ConversationComposer.tsx`; E2E
  `conversation-session-v4-queue.test.ts` with drag helpers in
  `packages/desktop/test/e2e/helpers/v4-conversation.ts`.
